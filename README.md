# CSR Writer v1.1.0

写向 NMPA/CDE 申报的中文临床试验总结报告初稿，适用于 I 到 III 期。

仓库里的夹具与示例数据全部为合成，不含任何真实受试者、研究者或机构信息。

## Mac 团队 · 在 Antigravity 里直接使用

**第一次安装**，把这一条发到 Antigravity 对话框：

```text
/goal 请在这台 Mac 上安装 CSR Writer。请将 https://github.com/huanglu1987/csr-writer/archive/refs/heads/master.zip 下载到临时目录并解压，用 /bin/bash 运行其中的 scripts/install-antigravity-mac.sh，看到“安装成功”后告诉我。
```

**开始写**，看到“安装成功”后，在 Antigravity 打开研究项目并新开会话。发下面这条，输入 `@` 时选中实际的研究资料夹。

```text
/goal 请用 csr-writer 从 @输入资料 生成 CSR 内部审阅初稿。按 SAP 补算能补的缺表，与已有定稿表对账。生成并打开 Word 核对正文、概要和附表，把 Word 路径发给我。缺哪些原件、哪些事项确需负责人决定，请在最后一次列清。
```

想先盘点资料用 `/plan`，表多要分章核查用 `/teamwork`，主要分析和敏感性分析不一致时可用 `/boost`。[按场景复制起草命令](docs/antigravity-csr-guide.md#commands)

**负责人怎么回？** 打开首稿旁的《集中审阅清单》，请对应负责人写明选哪项、为什么。回到生成 Word 的聊天窗口，把更新指令和负责人原话一起发给智能体，它会另存新版，并列出还没答的事项。[看一条统计回复怎样更新三处 Word 内容](docs/antigravity-csr-guide.md#answers)

## 一、装工具（整台电脑只做一次）

工具装一份就够，以后所有研究共用，不用每个项目装一遍。

在 Codex 里随便新建或打开一个会话，把下面这段发给它：

> 请帮我做这几件事，做完告诉我结果：
> 1. 把 https://github.com/huanglu1987/csr-writer.git 克隆到我的用户主目录下，
>    也就是 ~/csr-writer
> 2. 进去建一个 Python 虚拟环境，用 `pip install -e ".[source-office,models,visual]"` 安装
> 3. 在工具仓库用该环境的 Python 运行 `python -m unittest -v tests.test_antigravity_quickstart`，验证公开示例能生成首稿并回写两项答复

以测试进程退出码为 0 且末尾显示 `OK` 为准。
需要 Python 3.10 或以上版本。启用独立 R 复算需另装 R，渲染预检需安装 LibreOffice。Python 出稿程序可在本地运行。

**以后工具有更新**，跟它说一句"把 ~/csr-writer 更新到最新版"就行，
所有项目一起受益。

## 二、给每个研究建一个项目文件夹

工具是共用的，但**每个研究单独一个文件夹**，资料和生成的报告都放在自己的文件夹里，
互不干扰，以后归档、应对核查也清楚。

建一个文件夹，名字用研究编号，里面再建两个子文件夹：

```
~/csr-writer/            ← 工具，装一次，所有项目共用

~/CSR-ZYG-XXXX/          ← 这个研究的项目文件夹，在 Codex 里打开这一层
    输入资料/             ← 方案、SAP、TFL 都放这儿
    输出/                ← 生成的报告会放这儿
```

**每次要干活**：在 Codex 里打开这个项目文件夹
（界面上选"打开文件夹"，选到 `CSR-ZYG-XXXX` 这一层），然后直接说话。
工具在哪儿，下面的提示词里会告诉它。

## 三、准备资料

### 文件放哪

统统放进这个研究的 `输入资料/` 里，**不要往 `~/csr-writer` 里放**——
那是所有项目共用的工具，混进项目文件以后就乱了。

`输入资料/` 里可以这样组织，照搬即可：

```
CSR-ZYG-XXXX/
    输出/
    输入资料/
        方案_v3.0.docx                Word 原件，别用 PDF
        方案修订/                      各版修订案，也是 docx
        SAP_v2.0.docx
        TFL定稿_20260915/              统计给的最终结果
            t14-1-1-1.rtf             一张表一个 RTF 最好
            t14-2-2-1-1.rtf
            ...
        方案偏离清单.xlsx
        CRF样表.pdf
        伦理与知情同意/
            伦理批件.pdf                 盖章扫描件就行
            伦理委员会名单.pdf
            知情同意书样本_v2.0.pdf
        随机化方案与编号表.xlsx
        研究者与中心名单.docx
        研究基本信息与签字人.docx
```

文件名怎么起随你，Codex 会自己认。**但同一份东西改版之后，
新文件要用新名字**，别用同名覆盖——覆盖了追溯就对不上了。

### 一定要有的

| 资料 | 什么格式 | 找谁要 | 没有会怎样 |
|---|---|---|---|
| 研究方案，含全部修订案 | `.docx` | 临床运营 / 医学 | 研究设计定不下来，报告的框架搭不起来 |
| SAP | `.docx` | 统计负责人 | 分析集、统计模型、缺失值处理写不了 |
| 定稿 TFL（表、图、清单） | 一张表一个 `.rtf` 最好；整份 `.docx` 也行 | 统计编程 | 有逐例数据和可执行 SAP 时可补算缺表；两类来源均缺时，结果留待补充 |
| 方案偏离清单 | `.xlsx` 或 `.docx` | 临床运营 / 数据管理 | 第 10.2 节写不了 |
| 病例报告表样本 | `.pdf` 就行 | 数据管理 | 附录 16.1.2 缺，这是 E3 必交项 |
| 伦理批件、伦理委员会名单、知情同意书样本 | `.pdf` 就行（盖章扫描件常见） | 法规 / 临床运营 | 第 5 章伦理部分和附录 16.1.3 缺 |
| 研究者与研究中心名单 | `.pdf`、`.docx`、`.xlsx` 都行 | 临床运营 | 附录 16.1.4 缺 |
| 随机化方案与随机号表（随机研究） | `.xlsx` 或 `.docx` | 统计编程 | 附录 16.1.7 缺，这是 E3 必交项 |
| 表图清单的最终编号规则 | 一份清单即可，Codex 帮你转 | 统计编程 / 医学写作 | 正文里"详见表 X"对不上号 |
| 研究基本信息与签字人 | 一份清单即可 | 项目经理 / 法规 | 标题页出不来 |

### 有就更好的

| 资料 | 给了之后 |
|---|---|
| 盲态维护与揭盲记录 | 盲法那节能写成有依据的正文，而不是套话 |
| 试验药品批号与受试者对应表（用了多个批次时）| 附录 16.1.6 能补齐 |
| DMC/IDMC 章程和会议纪要 | 期中分析、数据监查的内容能落位 |
| SAE 和死亡病例经医学审核的结构化信息 | 个例叙述才能生成；没有的话工具不会去编经过 |
| MedDRA、WHODrug 的版本号 | 不良事件和合并用药的编码来源能写清楚 |
| 稽查证书、地区性附件登记 | 附录清单的提交状态更完整 |
| 中心实验室的方法与质控文件 | 附录 16.1.10 能补齐 |
| 参考文献清单 | 第 15 章能自动生成 |
| 关于是否开展 COA 开发的正式说明 | 工具照实转述项目决定。它不选、不验证、不开发量表 |

### 关于格式的几个提醒

**方案和 SAP 优先提供 DOCX，TFL 优先提供统计导出的单表 RTF。** 方案和 SAP 的 UTF-8 文本也可以直接摘录。只拿到 PDF 时可先起草能定位的内容，采用其中的关键条款或表格前应对照原页核实。

**伦理批件等附件可直接提供 PDF。** 工具登记文件。安装 PyMuPDF 后可提取有文本层的 PDF 并记录页码及文本块。纯扫描件进入集中核对清单，批准日期、批件编号和签章需依据原页确认。

**方案不用先把修订都接受掉再给它。** 工具会把插入、删除、隐藏文字都读出来单独列给你，
那正是要你留意的地方。为了"干净"先接受修订，反而把信息抹掉了。

**TFL 优先用 RTF。** 工具处理 RTF 是一张表一个文件、按表号逐个套值的，
统计用 SAS 直接导出的 RTF 正好是这个形态。整份 Word 的路径也支持，
只是测试覆盖没有 RTF 那么充分——特别是跨页重复表头、横纵向合并同时出现
这类复杂表头，目前还没有验证过。用 Word 版的话，这类表出来后自己多看一眼。

**Excel、清单类的不用你整理成什么特定格式**，可提供统计或运营的原件。新入口登记文件；需要引用表格内容时，由智能体核对工作表、行列、单位和版本。

## 四、开始写

将一个研究的资料放在同一文件夹，告诉智能体「用 CSR Writer 从这个文件夹生成内部审阅初稿」。也可从项目根目录直接运行：

```bash
python3 -m csr_writer draft-project --input-dir "/研究目录/输入资料"
```

工具在输入文件夹旁新建「输入资料_CSR初稿」，重跑时自动另建编号目录。它会读取原件、识别现行方案和 SAP、按表义及原始行列匹配统计结果、组装正文和附表、派生概要并汇总人工决定。可用 `--output-dir` 指定一个新目录。项目已有经确认的研究事实及冻结表映射时继续使用这些记录。遇到陌生表题，宿主智能体按[起草指南](docs/智能体起草指南.md)结合方案和 SAP 处理。

---

### 逐例数据与部分定稿表可混合出稿

使用同一个 `draft-project --input-dir` 入口。工具按表决定采用定稿、从逐例数据补算或暂缓采用。已有表与补算结果同时存在时逐格对账；冲突收录在集中审阅清单中。统计复核表和独立复算记录随 Word 交付。已接入两组量表应答率、Wilson 区间和 Newcombe 率差区间，以及观察病例连续变化的描述性分析。指定模型时可从原始记录完成 MMRM（含 Kenward–Roger）、固定中心及额外协变量 ANCOVA、单调正态回归或 FCS 多重插补、停药后完成数据或每轮 FCS 内的 MNAR 偏移、J2R/CIR 参考组插补、随机中心截距 MMRM 和 ANCOVA、中心随机治疗斜率与组别特异访视协方差、连续及分类结局的参考组插补、Cox/Breslow 及 CMH，并推导区间和双侧 P 值。安全性按实际给药、SAP 观察窗和受试者去重计算。审批状态始终按实际记录。支持的数据域、无法执行的模型及输出位置见[逐例统计说明](docs/智能体起草指南.md#从逐例数据计算统计表)。

## 五、出来的是什么

新入口生成 **CSR内部审阅初稿.docx** 和 **集中审阅清单.md**。Word 包含本轮实际写入的段落、统计表和待补处。审阅清单说明哪些章节已有正文，哪些只有原文摘录、统计表或资料缺口。逐节状态、来源原件指纹和续写计划同时保存在输出目录。

旧版合卷入口仍支持 annotated 和 clean 两种输出。数字追溯、方案到 SAP 到 TFL 到 CSR 的双向对照及视觉预检可按项目需要运行。可参看[视觉检查示例](examples/reference/视觉检查示例)。

## 六、它不做什么

这些是故意划的边界，不是没做完。

结果数值须来自已采用的统计原件，或依据本研究 SAP 从逐例数据推导。所需资料缺失时，保留来源缺口。

不判断某个不良事件和药物有没有关系。研究者在 CRF 里判了什么就照搬什么。

不代写申办方的医学评价，这个位置永远留给人。

源病历里没有的诊疗经过不会编，没有就写"待资料到位后补充"。

不判断资料是不是能递交了。所有检查都过，也只是说机器这一层没发现问题，
不等于医学、统计、法规同意了。

排版检查用的是 LibreOffice 渲染，和 Word 的分页、字体有差别，只能当粗筛。
最后还是要在 Word 里更新域、自己翻一遍。

还有一点要知道：这个工具目前还没在真实项目上用过，之前的验证都是拿模拟数据做的。
头一回用的时候多留个心眼，出来的东西该怎么审还怎么审。
