# CSR Writer v1.1.0

写向 NMPA/CDE 申报的中文临床试验总结报告初稿，适用于 I 到 III 期。

公司内部工具。仓库里有未公开研究的合成数据和内部写作规范，不要外传。

---

## 这是个什么东西

它是一个 Python 命令行工具，干活的代码都在 `csr_writer/` 里。
不是插件，也不是 Skill——那些只是让不同 AI 工具接上的壳：
`AGENTS.md` 给 Codex 看，`skills/csr-writer/SKILL.md` 给支持 Skill 的平台看，
`.claude-plugin/` 是早期遗留，现在没用。

**在 Codex 里不需要装插件。** 下面所有事都是对 Codex 说话，它替你敲命令。

---

## 第一步：让 Codex 装好

打开 Codex，把下面这段发给它：

> 请把 https://github.com/huanglu1987/csr-writer.git clone 到我的用户目录下，
> 进到仓库里建一个虚拟环境，用 `pip install -e .` 装好，
> 然后跑 `python3 -m unittest discover -s tests` 确认环境正常。
> 跑完把测试数量和结果告诉我。

它应该回你 `Ran 312 tests ... OK`。看到这个就说明环境没问题。

需要 Python 3.10 以上。依赖只有 python-docx、lxml、PyYAML。不需要模型 API。
LibreOffice 装不装都行，装了才有排版预检和缩略图墙，没装就跳过这步，不影响别的。

装好之后每次用，只要让 Codex 打开这个仓库目录就行，它会自己读 `AGENTS.md`。

## 第二步：把资料准备齐

**真实文件放在仓库外面**，比如 `~/csr-inputs/ZYG-XXXX/`。
不要拷进仓库：仓库是共享的，而且版本一混追溯链就断了。
工具只读这些文件，用 SHA-256 记版本；换了版本要重新核对，不能同名覆盖接着跑。

### 必须有的六样

| 资料 | 格式 | 一般找谁要 | 没有会怎样 |
|---|---|---|---|
| 研究方案，含修订历史 | DOCX | 临床运营 / 医学 | 研究事实、方法学章节都定不下来，骨架出不全 |
| SAP | DOCX | 统计负责人 | 分析集、模型、缺失值处理、终点分析方法只能留缺口 |
| 经确认的 TFL shell | DOCX，锁库前冻结 | 统计编程 | 没法提前建行列语义和表号映射 |
| 结果 TFL | 每张表一个 RTF 最好，DOCX 也支持 | 统计编程 | 数值章节全是缺口，clean 版出不来 |
| 表/图/清单的发表编号规则 | JSON 或经确认的映射表 | 统计编程 / 医学写作 | 正文交叉引用和第 14 章生成不稳 |
| 研究基本信息和签字人信息 | 经确认的清单 | 项目经理 / 法规 | 标题页和责任人信息生成不了 |

### 有就给、能多产出的九样

| 资料 | 给了之后 |
|---|---|
| 随机化、盲态维护、揭盲记录 | 9.4.3 分组方法和 9.4.6 盲法能写成有证据的正文 |
| DMC/IDMC 章程和会议结论 | 期中分析、数据监查的内容能落位 |
| SAE / 死亡病例经审核的事实卡 | 12.3.2 个例叙述才能生成；没有的话工具不会去推断经过 |
| 编码字典版本（MedDRA、WHODrug） | SOC/PT、ATC/药名这些数据驱动的行来源更清楚 |
| 稽查状态、地区性附件登记 | 16.0 附录清单的提交状态和位置更完整 |
| 参考文献和 claim ledger | 第 15 章和关键主张能确定性生成 |
| 委员会、实验室、中心资料 | 相应附录状态和方法描述能补齐 |
| COA 相关资料，或"不开展新 COA 开发"的批准说明 | 工具照实转述项目决定。它不选、不验证、不开发 COA |
| LibreOffice + PyMuPDF + Pillow | 能在 Word 人工复核之前先查未展开的域、空白页、非 A4，并出缩略图墙 |

### 还有七样是过程中生成、需要你点头的

这些不用事先准备，工具会在流程里做出来给你确认。不确认就卡住，不会自己往下走：

`study_facts`（五维研究事实，工具只反向扫描提示，不替你填）、
事实卡（facts 转成一页 Markdown 给人读，不让人直接批 JSON）、
冻结的 `tfl_map`、发表编号映射、附录状态计划、
方法学抽取事实卡、审阅决定记录。

完整说明和全部 13 道人工闸门（谁负责、不做会卡在哪）在
[docs/输入清单与人工闸门清单.md](docs/输入清单与人工闸门清单.md)，
**动手前把这份看完**。

## 第三步：开始写

在 Codex 里打开仓库，按阶段说话就行，不用背命令。

**开工，告诉它资料在哪：**

> 我要给 ZYG-XXXX 研究写 CSR 初稿。资料都在 ~/csr-inputs/ZYG-XXXX/ 下面：
> 方案是 protocol_v3.0.docx，SAP 是 sap_v2.0.docx，TFL shell 是 tfl_shell_20260801.docx。
> 请按 AGENTS.md 的流程开始，先记录这些文件的 SHA-256，然后带我把 study_facts 填出来。

**确认完研究事实，做结构和映射：**

> study_facts 我确认过了。请生成模块路由和骨架，告诉我哪些章节因为设计不适用被关掉了。
> 然后从 TFL shell 建映射提议，按分组给我审阅队列。

**锁库拿到结果之后：**

> 结果 TFL 在 ~/csr-inputs/ZYG-XXXX/tfl_results_20260915/。
> 请套值，然后生成 annotated 版本，把所有缺口和待确认的地方列给我。

**关闭缺口、出正式版：**

> 这几处我已经确认（逐条列出）。请更新审阅决定，重新生成 annotated 和 clean 两版，
> 再跑一遍排版预检，把缩略图墙给我。

几点经验：

一次只推一个阶段。别让它从方案一口气跑到成稿——中间每步都有要人点头的地方，
跳过去后面也会被卡住。

它报错停下来的时候先看错误码。**大部分硬失败是设计成这样的**，
比如 shell 和结果对不上表，它会停下来要你裁决，而不是自己猜一个。

想知道现在能出什么、还缺什么，让它出 annotated 版本，缺口都标在里面。

---

## 出来的是什么

两个 Word 文件。**annotated 版**把缺口、待医学负责人确认的地方、
每个数值的来源都标出来，给内部审阅用。**clean 版**是干净正文，
缺口没关完它出不来——故意的，免得半成品被当定稿递出去。

另外还有一批报告：数值溯源、QC 结果、缺口清单、双向追溯（方案→SAP→TFL→CSR 及反向）、
未被引用的 TFL 清单，以及排版预检的缩略图墙——把整份文档缩成一张图，
红黄绿标出问题页，扫一眼比在 Word 里翻快得多。样子看
[examples/reference/视觉检查示例](examples/reference/视觉检查示例)。

---

## 它不做什么

这些是故意划的边界，不是没做完。

不会写 TFL 里没有的数字。找不到就是缺口，不会推断出一个看着合理的值。

不做个案因果关系判定。研究者在 CRF 里判了什么就照搬什么。

不代写申办方的医学综合评价，这个位置永远留给人。

源病历里没有的临床经过不会编，没有就写"待资料到位后补充"。

不判断资料是不是能递交了。检查全过也只是说机器这层没发现问题，
不等于医学、统计、法规同意了。

排版预检用 LibreOffice 渲染，和 Word 的分页、字体回退有差别，只能当粗筛，
最后还是要在 Word 里更新域、翻一遍。

---

## 现在什么状态

v1.1.0，已冻结，312 项回归全绿。

**这个工具还没在真实数据上跑过**，目前所有验证都在合成项目上做的。
第一次拿真实项目用，建议当成一次正式演练来组织，让各环节真正的负责人
走一遍那 13 道确认，别一个人闷头跑完。

方法学章节的守卫有大约 7% 的对抗放行率，放行的都是语法不通的拼接句，
人扫一眼能看出来，不是读着顺但内容是编的那种。

SAE 叙述走的是最严的路子，只接受事先审过的整句，所以自动化程度最低，
每一例都要有人先把句子写出来确认。这是当初权衡后定的。
