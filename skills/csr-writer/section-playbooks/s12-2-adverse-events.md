# §12.2 不良事件——受控结果起草 playbook

## 适用范围

- 用于总体 AE 概要、TEAE/TRAE 汇总、按 SOC/PT 的事件分布，以及由事实路由激活的 AE 专项子节。
- 局部耐受性评分、生命体征、心电图和实验室结果分别写入其专项节；只有被采集并编码为 AE 的用药部位反应进入本节。
- SAE 个例医学叙述不在本 playbook 内起草。

## 最低输入

- 经审核的 AE/TEAE/TRAE 定义、收集期和编码字典版本。
- 安全性分析集定义及已确认的总体 AE、SOC/PT 和专项事件 TFL。
- 因果关系分类只可来自已审核 CRF、医学监查或 TFL 事实，不得由事件名称推断。

## 建议段落结构

1. 先说明分析集、事件定义、编码体系和汇总口径；缺少任一项时登记资料缺口。
2. 从总体概要中提炼最关键的发生情况；正文通常只选取最能回答安全性问题的结果，不逐项抄表。
3. 如有明确的高频事件、严重程度、后果或专项分层，可在对应子节描述，并引用支持表。
4. 医学解释或总体安全性结论单独成段，必须标记 `[待医学负责人确认]`。

## 数值与交叉引用

- 例数、比例、发生率、时间、严重程度分级、组间差异和排序所依赖的结果全部使用已绑定占位符。
- 正文每个结果只使用其语义角色对应的绑定，不得交换治疗组、TEAE/TRAE 或总体/专项事件。
- 表、图、清单只使用 `{{@ref:...}}`；不得写死编号。
- 同一段优先呈现少量关键结果，完整分布留在支持表中。

## 语义红线

- 不得将“与研究治疗相关”改写为工具自己的因果判定。
- 不得自主写“安全性良好”“风险可接受”“未发现新的安全性信号”或获益风险结论。
- 不得根据没有记录、没有表项或资料未提供推断事件未发生。
- 不得生成 SAE 的诊疗经过、转归或医学评价。
- 任何医学结论性语句都必须含 `[待医学负责人确认]`，并设 `confidence=inferred`、`needs_human=true`。

## 常见退审风险

- 只罗列总体百分比而不说明分析集、观察期和 TEAE 定义。
- 混淆 TEAE 与 TRAE，或把研究者因果判断写成报告作者结论。
- 把局部耐受性主动评分与编码为 AE 的用药部位反应合并。
- 只报告“无 SAE/无停药”而未给出经审核的来源。
- 正文堆叠所有 SOC/PT，遮蔽真正需要医学解释的事件模式。

## 溯源

每段记录来源定位、分析集、TFL 语义键、交叉引用实体、置信度和人工确认状态。若同一事件来自多个表，保留各表的角色，不合并成无来源的综合数值。

---

## 给写手的约束（不得写入正文）

- TEAE、TRAE、SAE、死亡、停药和重度事件的集合与角色不得互换或合并。
- 不得在正文提及写手、条件分支、绑定、占位符或数据处理流程。
- 关键安全性结果不足时只选用下一分区标准句，不得把缺失当作零事件。

## 证据不足时的标准表述（可写入正文，须按此措辞）

- 本节不良事件发生情况待相应统计结果到位后补充。
- 本节严重不良事件、死亡及导致停药事件情况待相应统计结果到位后补充。
- 本节结论基于经审核的安全性汇总，未涵盖尚未完成核实的事件资料。

## 文风规范

- 禁用表达：`汇总为`、`汇总结果为`、`可计算性为`及其他“XX 性为”字段式句法。
- 「经审核」「按预设」各自每节至多 1 次，仅用于首次界定来源；后文直接引用方案或 SAP。
- 每段至多 1 个分号，超过时拆为完整句。
- 单句不超过 60 字；较长限定条件应拆出并放在段末。
- 边界声明放在段末，不逐句重复免责或核查范围。
- 优先使用“主语 + 动作 + 结果”的完整句，不逐项念出角色名称和值。
- 零事件表述只能由数据条件化规则生成，不得在起草正文中硬编码。

## 1. 本节的权威依据

- ICH E3 §12.2 要求给出 AE 概要、展示、分析和按患者列表的追溯。
- ICH E3 §12.2.2 的示例表格实际放在 14.3.1，E3 Q&A Q6 已澄清。
- ICH E3 §12.3 将死亡、SAE 和其他重要 AE 与常规 AE 分开。
- ICH E3 章节树明确要求所有安全性表同时展示试验药与对照。
- 国家药监局2019年第88号公告确立 ICH E3 中国 CSR 基线。
- CDE 2020年第5号《药物临床试验期间安全信息评估与管理规范（试行）》为核查表已验证安全性依据。
- CDE 2023年第17号安全性信息问答为核查表已验证依据。
- CDE 2018-04-27 《药物临床试验期间安全性数据快速报告常见问题问答（1.0版）》在核查表中没有文号，不得自行补号。
- MedDRA 版本必须从项目数据管理/编码记录取得，不得由写手猜测。

## 2. 必须回答的问题清单

- [ ] 安全性分析集的名称、定义和计组原则是什么。
- [ ] AE、TEAE 和 TRAE 的定义与观察窗是什么。
- [ ] AE 使用什么字典和版本编码。
- [ ] 严重程度分级标准和版本是什么。
- [ ] 研究者因果关系分类如何映射为 TRAE。
- [ ] 总体 TEAE 和 TRAE 发生情况是什么。
- [ ] 是否有死亡、SAE、重度事件或导致永久停药的事件。
- [ ] 是否有导致临时停药、剂量降低或研究退出的事件。
- [ ] 是否有 AESI，定义和结果是什么。
- [ ] 按 SOC/PT 汇总时是否同时展示所有治疗组。
- [ ] 同名 PT 是否由父级 SOC 路径区分。
- [ ] 最常见 AE 的阈值是预设还是事后选择。
- [ ] 正文选取的事件是否由已确认排序/医学重要性决定。
- [ ] 局部耐受性主动评分与编码为 AE 的用药部位反应是否分开。
- [ ] TEAE/TRAE 成对表是否在正文中保持角色对应。
- [ ] 组别语义是否与 10.1/10.3 一致并经五组校验。
- [ ] 结论段的五个 v1.3 关键绑定是否全部到位。
- [ ] 如有 SAE 或导致停药事件，是否先陈述事件再改变结论措辞。
- [ ] 如关键绑定缺失，是否取消总体判断。

## 4. 数值红线与结论性表述规则

- 例数、比例、百分比、发生率、严重程度和组间结果全部使用占位符。
- 不得使用“多数”、“大部分”、“近七成”等模糊数量表述。
- 研究者记录的因果分类可作数据呈现，但写手不得自主判定因果。
- 不得根据无表项、无记录或资料未提供推断“无事件”。
- 安全性结论必须由 `{{@conclusion:SAFETY_TOLERABILITY_V1}}` 受控规则生成。
- 该规则至少绑定总体 TEAE、SAE、死亡、导致停药和重度事件。
- 无 SAE、无死亡、无导致停药且无重度事件时，可生成“总体耐受性良好”类措辞。
- 有 SAE、死亡、导致停药或重度事件时，必须先陈述已绑定事件结果，并取消上述套话。
- 任一关键绑定缺失时，不生成判断句，输出数据待到位提示。
- 三种分支都必须带 `[待医学负责人确认]`，且不得形成因果、获益-风险或申报建议。
- 数据条件化规则只改变措辞，不自动产生 SAE 医学叙述。

## 5. 推荐段落结构

- [段1] 分析集、观察窗、定义、编码与严重程度口径：3–5 句。
- [段2] 总体 TEAE/TRAE 概要：提炼主要发生情况，3–6 句，引概要表。
- [段3] 按 SOC/PT 的常见事件：选取关键模式，3–6 句，引平行表。
- [段4] 严重程度：客观陈述重度/高等级事件，2–5 句。
- [段5] 后果分层：导致降量、暂停、永久停药和退出分开写，3–6 句。
- [段6] AESI 或路由激活的专项：仅在 facts 为真时写，2–5 句。
- [段7] 局部耐受性 AE 子集：与主动评分分开，2–5 句。
- [段8] v1.3 关键事件句：在结论前陈述 SAE、死亡、停药和重度事件，2–4 句。
- [段9] 数据条件化总体评价：使用受控 token，1–3 句，待医学确认。
- 正文不罗列全部 SOC/PT；完整分布留在 14.3.1 表中。
- 每段 3–6 句；事件类别多时拆分小节而不堆在一段。

## 6. 常见退审问题

| 问题 | 如何规避 |
|---|---|
| 不说明分析集、观察窗和 TEAE 定义 | 将三者作为首段强制字段 |
| TEAE 与 TRAE 混用 | 使用独立语义角色，绑定顺序不可交换 |
| 同名 PT 在不同 SOC 下发生键冲突 | 使用 SOC/PT 父级路径，跨父级同名合法 |
| 五组列的试验组与安慰剂互换 | 与 10.1/10.3 组别帐户做语义校验 |
| 局部评分与 AE 子集混在一起 | 分开主动量表、观察体征和编码 AE |
| 只写“无 SAE”但没有绑定 | 将 SAE 计数作为结论必需单元格 |
| 有导致停药 AE 仍写“耐受性良好” | 由脚本分支改变措辞，先陈述事件 |
| 关键绑定缺失却仍生成判断 | 输出待数据提示并产生 QC 警告 |
| 将研究者因果评价写成报告作者判定 | 明确归因来源，不改写因果强度 |

## 7. 本节特有的易错点

- 一名受试者多个事件时，受试者发生率与事件次数不可混用。
- 按最重程度汇总与按事件等级计数是不同口径。
- 同一事件可同时出现在 TEAE、TRAE、SAE 和停药子集，不是重复错误。
- “无新的安全性信号”需要跨研究与医学监查证据，不是单节 TFL 可自动得出。
- 总体 TEAE 发生率高不能单独推导耐受性差，发生率低也不能推导良好。
- 严重性、严重程度和因果相关性是三个不同维度。
- 死亡的完整集合与 SAE 集合允许交叉，不得为去重而删除合法重叠。
- 数据驱动 SOC/PT 行在 shell 阶段延后，结果阶段按真实父级路径建键。
- 常见 AE 阈值必须预设或说明，不得为了得出好看的文本事后选阈值。
- SAE 叙述的诊疗、转归和医学评价仍属红线，本 playbook 只生成索引和汇总框架。

- [ ] AE 定义、观察窗、分析集和编码版本已确认。
- [ ] 每个治疗组与合计列语义已校验。
- [ ] TEAE/TRAE 和各后果子集的角色未交换。
- [ ] SOC/PT 父级路径可区分跨 SOC 同名 PT。
- [ ] 所有数值使用占位符。
- [ ] 所有表图使用受控交叉引用。
- [ ] 结论段五个关键绑定已审计。
- [ ] 有重要事件时已先陈述并改变措辞。
- [ ] 关键绑定缺失时只输出待数据提示。
- [ ] 未生成因果判定、SAE 医学叙述或获益-风险结论。
