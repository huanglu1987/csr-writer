# §12.3.1 死亡、其他 SAE 和其他重要 AE 列表——共享 playbook

> 供 §12.3.1.1、§12.3.1.2 和 §12.3.1.3 共用。
> 这是列表索引与集合核对 playbook，不生成 SAE 医学叙述。

## 适用范围

- §12.3.1.1：研究期间死亡的完整集合。
- §12.3.1.2：除死亡集合外及与死亡集合允许交叉的其他 SAE。
- §12.3.1.3：方案或医学审阅预定义的其他重要 AE。
- 详细列表通常置于 14.3.2；正文说明集合、计数和交叉关系。
- 受试者标识只使用递交允许的脱敏标识，不在工具日志保存原始身份信息。

## 最低输入

- 经冻结的 AE/SAE 数据、死亡状态、结局和重要事件分类。
- PV 与临床数据库的数据核对结果及截止日期。
- 安全性分析集和所有随机/治疗受试者的账户信息。
- 14.3.2 列表映射、16.3.1 CRF 附件状态及经确认的叙述索引。
- 医学负责人确认的“其他重要 AE”定义，不能由写手从严重程度猜测。

## 给写手的约束（不得写入正文）

- 死亡、其他 SAE 和其他重要 AE 的集合边界沿用经确认定义，不得人为互斥或去重。
- 不得在正文暴露写手、映射、绑定、去重步骤或内部状态。
- 清单未闭合时只选用下一分区标准句，不得将未列出解释为未发生。

## 证据不足时的标准表述（可写入正文，须按此措辞）

- 本节死亡及其他严重不良事件清单待经确认的数据核对完成后补充。
- 本节其他重要不良事件范围待医学负责人确认。
- 本节结论基于已完成核对的事件清单，未涵盖尚未完成核实的事件资料。

## 文风规范

- 禁用表达：`汇总为`、`汇总结果为`、`可计算性为`及其他“XX 性为”字段式句法。
- 「经审核」「按预设」各自每节至多 1 次，仅用于首次界定来源；后文直接引用方案或 SAP。
- 每段至多 1 个分号，超过时拆为完整句。
- 单句不超过 60 字；较长限定条件应拆出并放在段末。
- 边界声明放在段末，不逐句重复免责或核查范围。
- 优先使用“主语 + 动作 + 结果”的完整句，不逐项念出角色名称和值。
- 零事件表述只能由数据条件化规则生成，不得在起草正文中硬编码。

## 1. 本节的权威依据

- ICH E3 §12.3.1 要求分别列出死亡、其他 SAE 和其他重要 AE。
- ICH E3 §12.3.1.1 是死亡的唯一完整集合。
- ICH E3 Q&A Q5 明确死亡集合与其他 SAE 集合允许交叉，不得人为互斥。
- ICH E3 §14.3.2 是死亡、其他严重和重要 AE 列表的表格归位。
- ICH E3 §16.3.1 是死亡、其他 SAE 或 AE 导致退出的 CRF 归位。
- ICH E3 §12.2 与 §12.3 要求常规 AE 汇总和关键事件列表分层呈现。
- 国家药监局 2019 年第 88 号公告确立 ICH E3 中国 CSR 基线。
- CDE 2020 年第 5 号《药物临床试验期间安全信息评估与管理规范（试行）》为核查表已验证依据。
- CDE 2023 年第 17 号安全性信息问答为核查表已验证依据。
- `CDE申报要求核查表.md` 未验证的文号一律不得补入本节。

## 2. 必须回答的问题清单

- [ ] 安全性数据截止日期和数据库版本是什么。
- [ ] 死亡集合是否覆盖所有研究期间死亡，不限是否为 SAE 或是否相关。
- [ ] 死亡受试者是否也在适用的 SAE 集合中保留合法交叉。
- [ ] SAE 定义和严重性标准来自哪个方案/法规版本。
- [ ] “其他重要 AE”的项目定义是什么，谁确认了分类。
- [ ] 事件计数与受试者计数是否分开。
- [ ] 每个受试者多个 SAE 是否被正确表示。
- [ ] 各组关键计数是否与 §12.2 总体概要一致。
- [ ] 导致永久停药、退出或剂量调整的事件是否进入适用集合。
- [ ] 事件发生期、治疗期和随访期边界是否清楚。
- [ ] 事件术语是否采用已确认的 MedDRA 版本。
- [ ] 严重程度与严重性是否没有混用。
- [ ] 因果关系是否明确标作研究者/PV 记录，而非写手判断。
- [ ] 14.3.2 是否包含规定字段并与正文计数一致。
- [ ] 16.3.1 附件状态是否在 16.0 清单中可追溯。
- [ ] 无事件结论是否有已确认零值绑定，而非无记录推断。
- [ ] 个体标识是否符合脱敏和申报显示规则。
- [ ] 叙述索引是否与 §12.3.2/14.3.3 一一对应。

## 4. 数值红线与结论性表述规则

- 死亡人数、SAE 人数、事件数、发生率、天数和治疗阶段全部用占位符。
- 列表中的年龄、剂量、日期、时间和实验室值同样不得手打。
- 事件术语本身不是数值，但其 MedDRA 编码和版本必须来自审核来源。
- “无死亡/无 SAE/无其他重要 AE”只有对应集合的经确认零值绑定时可写。
- 缺少集合或核对结果时，写“待安全性数据核对完成”，不得写“未见”。
- 本节不生成“与研究药明确相关”等自主因果判断。
- 本节不生成“风险可接受”“安全性良好”或获益风险结论。
- 若需对集合完整性作结论，必须标 `[待医学负责人确认]` 并绑定核对状态。
- 死亡与 SAE 的交叉不能通过相减或去重算法推导正文人数。
- 其他重要 AE 的纳入不能只由严重程度数值触发，须有分类事实。

## 5. 推荐段落结构

### §12.3.1.1 死亡

- [段1] 数据范围和完整集合定义：2–4 句。
- [段2] 经确认的死亡人数、治疗组和时间范围：2–5 句，引用 14.3.2。
- [段3] 与 SAE 集合的交叉说明：1–3 句，不做医学解释。
- [段4] 叙述和 CRF 的索引：1–3 句。

### §12.3.1.2 其他严重不良事件

- [段1] SAE 定义、分析集和截止日期：2–4 句。
- [段2] 受试者数与事件数：3–5 句，分开计数口径。
- [段3] SOC/PT 或结局概要：3–6 句，只选关键事实。
- [段4] 与死亡集合、停药集合的交叉：2–4 句。
- [段5] 叙述索引：1–2 句。

### §12.3.1.3 其他重要不良事件

- [段1] 项目预设定义和分类来源：2–4 句。
- [段2] 集合规模和事件类型：3–5 句。
- [段3] 导致停药、退出或剂量调整的客观后果：2–5 句。
- [段4] 列表与叙述位置：1–3 句。

正文只作集合概要和导航，诊疗经过、医学解释及详细转归留给人工叙述。

## 6. 常见退审问题

| 问题 | 如何规避 |
|---|---|
| 死亡集合只保留研究者判定相关事件 | §12.3.1.1 纳入所有研究期间死亡 |
| 为避免重复而从 SAE 表删除死亡者 | 按 Q&A Q5 保留合法交叉并说明 |
| 把重度 AE 当作 SAE | 分开 severity 与 seriousness 字段 |
| 受试者数与事件数混写 | 使用独立绑定角色并在句中标明口径 |
| “其他重要 AE”由写手临时决定 | 只使用方案/医学负责人确认的分类 |
| 无记录被写成无事件 | 只有完整集合零值绑定才能写“无” |
| 14.3.2 与正文计数不一致 | 装配前做确定性集合对账 |
| 因果关系被写成作者结论 | 明确“研究者记录为”，不增强语气 |
| 列表泄露身份信息 | 使用申报允许标识，日志只存哈希/语义键 |
| 缺少数据截止日期 | 每个集合首段绑定同一冻结版本 |
| 叙述与列表对象不一致 | 生成双向索引并硬失败报告差异 |
| 关键 CRF 状态从清单消失 | 16.0 始终保留 16.3.1 状态条目 |

## 7. 本节特有的易错点

- “死亡”是结局，“致死性 SAE”是事件属性，集合不必一一等同。
- 一名受试者可有多个 SAE，但死亡受试者只在死亡人数中计一次。
- SAE 发生日期、知悉日期和报告日期用途不同，不得互换。
- SAE 严重性标准可多选，不能把多项标准当作多个事件。
- 住院延长与既有住院的背景需医学核实，写手不能自行解释。
- 其他重要 AE 可包含导致停药但不满足 SAE 的事件。
- 退出研究与永久停药不是同一后果。
- 事件恢复不代表不重要，事件未恢复也不自动构成严重。
- 同名 PT 在不同 SOC 下必须保留父级路径。
- PV 数据和临床数据库可能在截止时点不同，未核对不得合并。
- 14.3.2 的 E3 类别与独立流水表号是两层映射。
- 列表、叙述和 CRF 三者的存在状态必须各自记录。
