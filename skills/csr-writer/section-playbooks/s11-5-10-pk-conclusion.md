# §11.5.10 PK 结论——数据条件化 playbook

> 适用于由 `M-PK-NCA` 或 `M-TOPICAL-PK` 激活的 PK 结论节。
> 本节不重复完整结果，只综合已经陈述的可定量性、参数可计算性和采样局限。

## 适用范围

- 外用制剂、系统给药和多次给药研究均可使用，但必须沿用相应 PK 模块的事实。
- 外用制剂不得预设“系统暴露低”；BLQ 或参数不可计算不等于无系统暴露。
- 本节必须位于 11.5 同级子节的最后，不先于血药浓度和 PK 参数结果。
- 结论由确定性规则 `PK_CONCLUSION_V1` 展开，写手不得选择措辞分支。
- 所有关键角色均来自本节已确认的最小结果集合。

## 最低输入

- PK 分析集定义和纳入排除规则。
- 血药浓度及 BLQ 汇总结果。
- 可定量采样时点的汇总结果。
- Cmax 和 AUC 的可计算状态。
- 参数不可计算的经审核原因。
- 生物分析方法 LLOQ。
- 实际采样对预设时点的覆盖完整性。
- 相关 TFL 的已确认交叉引用。

## 给写手的约束（不得写入正文）

- 只输出允许的结果占位符和 `{{@conclusion:PK_CONCLUSION_V1}}`。
- 不得自行比较阈值、选择结论分支或把 BLQ 解释为无吸收。
- 不得在正文提及写手、工具、证据包、绑定、语义键、映射或置信状态。
- 不得把本分区的禁止事项改写成 CSR 句子。
- 不得手写任何比例、时点数、浓度、LLOQ、参数值或范围。
- 缺少关键角色时保留缺失分支，不用其他 PK 表代替。

## 证据不足时的标准表述（可写入正文，须按此措辞）

- 本节 BLQ 比例及可定量时点情况待相应统计结果到位后补充。
- 上述为可计算参数的汇总结果，不代表全部采样时点。
- 现有资料不足以完整表征系统暴露，相关结论受到采样覆盖和参数可计算性的限制。
- 本节 PK 结论待关键结果完成确认后补充。

## 文风规范

- 禁用表达：`汇总为`、`汇总结果为`、`可计算性为`及其他“XX 性为”字段式句法。
- 「经审核」「按预设」各自每节至多 1 次，仅用于首次界定来源；后文直接引用方案或 SAP。
- 每段至多 1 个分号，超过时拆为完整句。
- 单句不超过 60 字；较长限定条件应拆出并放在段末。
- 边界声明放在段末，不逐句重复免责或核查范围。
- 优先使用“主语 + 动作 + 结果”的完整句，不逐项念出角色名称和值。
- 零事件表述只能由数据条件化规则生成，不得在起草正文中硬编码。

## 1. 本节的权威依据

- ICH E3 §9.5.4 要求说明药物浓度测定方法和相关信息。
- ICH E3 的结果章节要求报告与研究目标和预设分析对应的结果。
- ICH E3 Q&A Q1/Q4 允许按研究设计重排、重命名并新增临床药理章节。
- 当前正式结构将 PK 评价置于 11.5，并将 PK 结论置于同级最后的 11.5.10。
- ICH E3 §13 要求总体讨论基于前文结果，本节不得替代第 13 章。
- 国家药监局 2019 年第 88 号公告确立 ICH E3 为中国 CSR 结构基线。
- `CDE申报要求核查表.md` 未给出本节专属且已验证的额外文号，不得自行补写。
- 规格 §1.2 禁止工具自主形成医学和获益风险结论。
- 规格 §1.2.1 要求结论性表述与经审核数据条件绑定。
- 规格 §3 要求所有统计数值由 datapack 确定性填充。
- `骨架审阅意见-核实与应对.md` 要求外用制剂 PK 交代 BLQ、LLOQ 和参数可计算性。

## 2. 必须回答的问题清单

- 使用的是哪个 PK 分析集。
- BLQ 比例是否有经审核的结果。
- 哪些预设采样时点获得可定量结果。
- 可定量时点数是否有明确口径。
- Cmax 是否可计算。
- AUC 是否可计算。
- 不可计算的具体原因是否已陈述。
- 生物分析方法 LLOQ 是否已陈述。
- 实际采样覆盖是否完整。
- 单次给药与稳态阶段是否分别呈现。
- 结论是否仅限数据支持的暴露特征。
- 是否错误使用“未检测到”。
- 是否错误使用“系统暴露低”。
- 是否把不可计算误写为无暴露。
- 是否说明外推受到的限制。
- 关键角色缺失时是否取消判断句。
- 结论是否标记 `[待医学负责人确认]`。

## 4. 数值红线与结论性表述规则

- BLQ 比例必须使用 `blq_ratio` 对应的完整占位符。
- 可定量时点数必须使用 `quantifiable_timepoint_count` 占位符。
- Cmax 和 AUC 可计算状态必须使用各自角色，不得由写手判断。
- LLOQ 必须来自 `lloq` 角色，不得从方法名称猜测。
- 不可计算原因必须来自 `noncalculable_reason` 角色。
- 采样覆盖完整性必须来自 `sampling_coverage_complete` 角色。
- 所有角色在结论 token 之前逐一陈述。
- 取值脚本在关键角色齐全后才展开结论。
- 可定量性和参数完整时，只允许描述“可用于描述所观察的系统暴露特征”。
- BLQ 比例达到保守触发条件、参数不可计算或采样不完整时，先陈述限制。
- 限制分支不得出现“系统暴露低”。
- 关键角色缺失时不生成系统暴露判断。
- 任何分支均不得生成剂量推荐或获益风险结论。
- 结论段必须保留 `[待医学负责人确认]`。

## 5. 推荐段落结构

- [段1] 分析集、给药阶段和采样设计，2–3 句。
- [段2] BLQ 比例和可定量时点，2–4 句，引用浓度表。
- [段3] Cmax、AUC 可计算状态与参数汇总，2–4 句，引用参数表。
- [段4] LLOQ、不可计算原因和采样覆盖限制，2–4 句。
- [段5] 数据条件化 PK 结论，1–3 句。
- 结论段只放 `PK_CONCLUSION_V1` 展开的句子，不重复手写判断。
- 单次给药与稳态结论不同，应在结果段分开，结论段说明适用范围。
- 超过 6 句的参数罗列应留在表中，正文只提炼关键解释条件。

## 6. 常见退审问题

| 问题 | 如何规避 |
|---|---|
| 把 BLQ 写成未吸收 | 同时报告 BLQ 比例、LLOQ、可定量时点和采样覆盖 |
| 只写“系统暴露低” | 由条件化规则决定是否允许描述暴露特征 |
| 参数不可计算但未说明原因 | 强制绑定 `noncalculable_reason` |
| 未报告 LLOQ | 强制绑定分析方法 LLOQ |
| 混淆单次与稳态 | 保留 D1/D28 等阶段维度并分段陈述 |
| 只报告 Cmax 不报告 AUC 可计算性 | 两个角色分别绑定并逐一陈述 |
| 采样不足仍作完整 PK 表征 | 采样覆盖不完整进入限制分支 |
| 将不可计算解释为零 | 不可计算状态以文字判定呈现，不转成数值零 |
| 结论引入前文未出现的结果 | 每个结论角色必须先在本节结果段出现 |
| 结论没有人工确认标记 | 条件 token 段固定保留医学确认标记 |

## 7. 本节特有的易错点

- t1/2 是参数名，不应把其中字符识别为结果数值。
- AUC0-∞ 是参数名，不应把下标字符识别为裸统计数字。
- LLOQ 是方法学界限，不等同于观测浓度或零值。
- BLQ 比例的分母可能是样本、时点或受试者，必须沿用 SAP 口径。
- 可定量时点数不等同于可计算参数的受试者数。
- Cmax 可计算不自动意味着 AUC 可计算。
- AUC 不可计算可能源于末端相不足，不必然源于全部样本 BLQ。
- 外用面积、皮肤状态和涂布部位可能影响暴露，但无预设分析时不外推。
- 幂函数模型的线性结论不能由肉眼比较剂量组均值替代。
- 低系统暴露不等同于局部安全，也不等同于无药物相互作用风险。
- 参数单位必须沿用 TFL，不得在结论段自行换算。
- 分析方法变更或样本重测必须在方法和偏离资料中有来源。

- 七个关键角色的顺序与请求契约一致。
- 所有角色均在结论 token 前出现。
- 所有统计值均仍为完整占位符。
- 表号均使用交叉引用占位符。
- 未出现内部流程语言。
- 未出现手写“系统暴露低”。
- 不可计算时已说明原因和 LLOQ。
- 缺失分支没有判断句。
- 结论段含医学确认标记。
- 元数据可追到方案、SAP 和 TFL。
