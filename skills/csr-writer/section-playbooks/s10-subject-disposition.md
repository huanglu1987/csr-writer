# §10.1 受试者处置——受控执行 playbook

## 范围

- 汇总筛选、随机、治疗、完成/退出及分析集纳入情况。
- 逐受试者宽表只登记表级来源，不把受试者标识写入 datapack 或正文。
- 处置人数与分析集人数必须分别绑定，不得互相替代。

## 最低输入

- 经审核的受试者处置定义和分析集定义。
- 处置汇总与分析集汇总的语义键。
- 对应 TFL 的已确认交叉引用实体。

## 硬约束

- 所有人数、比例、日期和组别结果必须使用取值占位符。
- 表号只能使用 `{{@ref:...}}`，不得写成正文数字。
- 缺少退出原因或分析集判定来源时留空并记录缺口，不推断。
- 不在正文或元数据中输出筛选号、随机号或可识别日期。

## 溯源

逐段记录方案/SAP 定位、处置与分析集 TFL、置信度和人工确认状态。

---

## 给写手的约束（不得写入正文）

- 退出原因沿用经审核的分类；不得自行合并、拆分或改写分类。
- 不得在正文提及写手、工具、证据包、绑定状态或其他起草流程。
- 处置与分析集来源不足时，只能选用下一分区的标准表述。

## 证据不足时的标准表述（可写入正文，须按此措辞）

- 本节完成与退出情况待相应统计结果到位后补充。
- 本节分析集纳入情况待相应统计结果到位后补充。
- 退出原因按经审核的分类呈现。

## 文风规范

- 禁用表达：`汇总为`、`汇总结果为`、`可计算性为`及其他“XX 性为”字段式句法。
- 「经审核」「按预设」各自每节至多 1 次，仅用于首次界定来源；后文直接引用方案或 SAP。
- 每段至多 1 个分号，超过时拆为完整句。
- 单句不超过 60 字；较长限定条件应拆出并放在段末。
- 边界声明放在段末，不逐句重复免责或核查范围。
- 优先使用“主语 + 动作 + 结果”的完整句，不逐项念出角色名称和值。
- 零事件表述只能由数据条件化规则生成，不得在起草正文中硬编码。

## 1. 本节的权威依据

- ICH E3 §10.1 要求对进入研究、完成和早停的受试者进行清晰账户式说明。
- ICH E3 §10.2 要求说明方案偏离，本节只建立处置与后续偏离节的衔接。
- ICH E3 第14章支持 14.1.x 受试者处置与分析集汇总。
- 国家药监局2019年第88号公告将 ICH E3 作为 CSR 基线。
- CDE 2021年第63号数据管理和统计分析相关指导原则支持对分析集和统计处理的追溯。
- 2020年第57号《药物临床试验质量管理规范》第五十五条要求源数据与报告数据一致。
- 本节的真相源是已确认方案、SAP、受试者处置 TFL 和数据处理记录。
- 本 playbook 不声称任何「未查证到」的 CDE 条款。

## 2. 必须回答的问题清单

- [ ] 签署知情同意、筛选、入组和随机的口径分别是什么。
- [ ] 实际进入每个治疗组的人数是什么。
- [ ] 实际接受研究治疗的人数是什么。
- [ ] 完成研究治疗和完成研究的口径是否分开。
- [ ] 退出研究治疗和退出研究的口径是否分开。
- [ ] 早停原因是否互斥，是否有主要原因定义。
- [ ] 每一早停原因的分母是否一致。
- [ ] 是否有受试者随访失败、撤回同意或行政性终止。
- [ ] 因 AE、疗效不佳、违约或其他原因早停的类别是否与 TFL 一致。
- [ ] 进入 FAS、mFAS、SS、PKS 等各分析集的人数是什么。
- [ ] 每个分析集的排除人数和排除原因是什么。
- [ ] 分析集名称与 10.3 的已确认事实是否逐字一致。
- [ ] 受试者处置数与随机化、给药、暴露和安全性人数是否能对账。
- [ ] 多个治疗期或队列是否分别对账。
- [ ] 是否有重复随机、未接受治疗或跨组给药的特殊情况。
- [ ] 是否需要 CONSORT 式受试者流程图。
- [ ] 逐受试者清单是否仅作表级登记，未展开识别信息。
- [ ] 数据截止后受试者状态更新是否已锁定。

## 4. 数值红线与结论性表述规则

- 筛选、入组、随机、治疗、完成、退出和分析集人数必须使用占位符。
- 所有百分比、日期、时间长度和组间差异必须使用占位符。
- 方案计划样本量是方案事实，只可通过 facts 白名单，不得与实际人数混用。
- “大部分受试者完成研究”是未溯源的模糊数量表述，禁止。
- “退出率较低”属判断性表述，未定义参照时不生成。
- “两组处置情况均衡”不得由写手自主判定。
- 如需说明处置对解释的影响，必须有已确认统计或医学评估并标记 `[待医学负责人确认]`。
- 表图引用仅使用 `{{@ref:...}}`，不得写死号码。
- 结果缺失时输出 source_gap，不根据方案计划人数推断实际人数。

## 5. 推荐段落结构

- [段1] 受试者流程的口径：仅说明数据截止、处置定义和分组，2–3 句。
- [段2] 筛选、入组、随机和实际治疗：提炼关键帐户数，3–5 句，引处置表。
- [段3] 完成研究治疗与完成研究：明确两种口径，2–4 句。
- [段4] 早停情况：按预设主要原因及组别提炼，3–6 句。
- [段5] 分析集帐户：按 10.3 的名称与定义陈述纳入情况，3–5 句。
- [段6] 排除或特殊处置：仅有已确认记录时书写，2–4 句。
- [段7] 追溯句：引处置表、分析集表和必要的流程图，1–2 句。
- 每段只回答一个帐户问题，不将方法、结果和解释混成一段。
- 正文只提炼关键流转，完整原因分布保留在表中。
- 每段建议 3–6 句，超过 8 句时拆分。

## 6. 常见退审问题

| 问题 | 如何规避 |
|---|---|
| 随机人数与处置表不一致 | 以已确认口径对账，冲突时硬失败 |
| “完成治疗”和“完成研究”混用 | 引用方案定义并分开计数 |
| 退出原因百分比分母不一致 | 从 TFL 元数据取分母，不由文本推断 |
| 只列主要原因，遗漏其他重要退出 | 表内全量覆盖，正文提炼但不隐去重要事实 |
| 分析集名称被强制大写 | 保留已确认的 FAS/mFAS/PKS 等原名 |
| 纳入人数与 10.3 定义不对应 | 从同一已确认 facts/SAP 派生，禁止重新表述 |
| 用方案计划人数填实际结果 | 计划值与实际值分层，实际值必须来自 datapack |
| 逐人宽表泄露识别信息 | 只登记表级元数据，不建受试者单元格键 |

## 7. 本节特有的易错点

- 签署知情同意者不必然等于筛选者，必须按项目定义。
- 入组与随机在非随机或分段研究中可能不同。
- 已随机但未给药的受试者不得静默消失。
- “退出治疗”不等于“退出研究”，后续随访可能继续。
- 撤回同意应按实际范围记录，不默认为撤回全部数据使用。
- 分析集排除可能在盲态数据审核会后确定，要绑定最终版本。
- 处置帐户不应为了对上表格而静默合并类别。
- 多期或交叉研究需区分受试者数和暴露期数。
- 安全性分析集常以实际治疗计组，不得默认与随机组一致。
- 受试者处置图不能代替分析集排除理由。

## 8. 发布前检查

- [ ] 处置口径已与方案和 SAP 对齐。
- [ ] 各阶段帐户能对账或有明确差异解释。
- [ ] 所有实际人数、比例和日期使用占位符。
- [ ] 分析集名称保留项目原始大小写。
- [ ] 每个分析集的定义与人数可双向追溯。
- [ ] 退出原因未被选择性省略。
- [ ] 逐人清单未展开至 datapack 或正文。
- [ ] 表图使用受控交叉引用。
- [ ] source_gap 未被合理补全。
- [ ] 输出不含受试者标识、可识别日期或机构信息。

## 9. 账户平衡的确定性检查

- [ ] 签署同意人数与筛选人数的口径已解释。
- [ ] 筛选失败者不会进入随机人数。
- [ ] 已随机但未给药者在处置账户中可见。
- [ ] 实际给药计组与随机计组的差异已记录。
- [ ] 完成研究治疗者与完成全部随访者已分开。
- [ ] 各早停原因合计与早停总数能对账。
- [ ] 多选原因表未被错当互斥账户。
- [ ] 每个分析集人数均可追至最终判定记录。
- [ ] 受试者流程图与处置表使用同一数据截止。
- [ ] 跨期受试者未被重复计为独立受试者。
- [ ] 数据锁定后的处置更新有版本和理由。
- [ ] 对账差异不会被四舍五入或百分比遮蔽。
- [ ] 不可对账时发布门禁为硬失败。
- [ ] 每个正文计数均有单一语义键。
- [ ] 已审结果未被方案计划值覆盖。
- [ ] 所有差异项均进入人工可读的对账报告。
