# §13 讨论和总体结论——已确认正文条件化 playbook

> 本节只能从已确认正文派生。
> `confirmed_body_binding_keys` 是硬边界，不允许本节从 TFL 选择任何新结果。

## 适用范围

- 综合研究目标、主要探索性或确证性结果、PK 关键发现和安全性结果。
- 讨论研究局限及结果可解释范围。
- 不独立读取全量 TFL，不重新排序有利和不利结果。
- 不生成申报建议、开发建议或“符合 CDE 要求”类判断。
- 结论由 `OVERALL_CONCLUSION_V1` 确定性展开。

## 最低输入

- 已确认的研究目的正文。
- 已确认的受试者处置和分析集正文。
- 已确认的主要终点结果正文。
- 已确认的 PK 关键发现正文。
- 已确认的 TEAE 汇总正文。
- 已确认的 SAE、死亡和导致停药事件正文。
- 已确认的研究局限正文。
- 与上述正文完全一致的结果键清单及哈希。

## 给写手的约束（不得写入正文）

- 只能复用 `confirmed_body_binding_keys` 中的结果，不得引入新数值。
- 不得直接读取未确认 TFL 或从多张表选择更有利结果。
- 不得形成最终获益风险结论或推进开发建议。
- 不得在正文提及写手、工具、派生流程、证据包、绑定、映射或置信状态。
- 不得把“不得引入新结果”等流程规则写成正文句子。
- 任一关键结果缺失时使用标准表述并取消总体判断。

## 证据不足时的标准表述（可写入正文，须按此措辞）

- 本研究总体结论待主要终点、关键安全性事件和药代动力学结果完成确认后补充。
- 本节结论基于已确认的正文结果，未引入正文未报告的新结果。
- 现有资料不足以形成总体获益风险结论，相关判断待医学负责人确认。
- 本节结论基于已完成核实的研究资料，未涵盖尚未完成核实的结果。

## 文风规范

- 禁用表达：`汇总为`、`汇总结果为`、`可计算性为`及其他“XX 性为”字段式句法。
- 「经审核」「按预设」各自每节至多 1 次，仅用于首次界定来源；后文直接引用方案或 SAP。
- 每段至多 1 个分号，超过时拆为完整句。
- 单句不超过 60 字；较长限定条件应拆出并放在段末。
- 边界声明放在段末，不逐句重复免责或核查范围。
- 优先使用“主语 + 动作 + 结果”的完整句，不逐项念出角色名称和值。
- 零事件表述只能由数据条件化规则生成，不得在起草正文中硬编码。

## 1. 本节的权威依据

- ICH E3 §13 规定讨论和总体结论，并要求结合研究目标解释结果。
- ICH E3 §8 提供研究目标，是本节组织讨论的起点。
- ICH E3 §10–§12 提供受试者、疗效、临床药理和安全性事实。
- ICH E3 §13 明确本节不应引入前文未报告的新结果。
- ICH E3 §2 Synopsis 必须与已确认正文和总体结论一致。
- ICH E3 Q&A Q1/Q4 允许按研究设计调整结果章节，但不改变证据一致性要求。
- 国家药监局 2019 年第 88 号公告确立 ICH E3 中国 CSR 结构基线。
- `CDE申报要求核查表.md` 未授权工具生成“申报就绪”或“符合 CDE”结论。
- 规格 §1.2 禁止工具自主进行获益风险判断和医学因果判定。
- 规格 §1.2.1 要求结论性表述由关键数据条件确定。
- 规格 §4 P6 要求从 CSR 反向追到 SAP、方案和 TFL。
- M4 跨章机制要求 Synopsis 从已确认正文派生，不独立起草。

## 2. 必须回答的问题清单

- 研究目标是什么。
- 主要终点结果是否已在正文确认。
- 分析定位是探索性还是确证性。
- PK 关键发现是否已在正文确认。
- PK 结果是否存在 BLQ 或参数可计算性限制。
- TEAE 总体结果是否已在正文确认。
- 是否存在 SAE。
- 是否存在死亡。
- 是否存在导致停药事件。
- 是否存在其他需要优先讨论的重要安全性事件。
- 受试者数量和随访是否限制解释。
- 是否存在方案偏离或缺失数据限制。
- 讨论是否覆盖研究目标而非逐表复述。
- 是否先陈述重要不利结果。
- 是否避免引入新数值。
- 是否避免形成开发推进建议。
- 是否避免形成申报合规结论。
- 任一关键绑定缺失时是否取消总体判断。
- 获益风险措辞是否保留医学负责人确认。

## 4. 数值红线与结论性表述规则

- 所有结果只使用前文已确认的完整占位符。
- 本节不得建立新的 TFL 结果角色。
- 每个角色必须在总体结论 token 之前出现。
- `primary_endpoint_result` 只复用前文终点结果。
- `pk_key_finding` 只复用前文 PK 关键发现。
- `teae_result` 只复用前文总体 TEAE 结果。
- SAE、死亡和停药计数分别绑定，不得互换。
- 任一关键角色缺失时进入缺失分支。
- 有 SAE、死亡或停药事件时，必须先承认关键安全性事件。
- 有关键安全性事件时不得生成有利获益风险表述。
- 无关键事件时仍不自动生成最终有利获益风险结论。
- 所有分支均把最终判断留给医学负责人。
- 不生成“建议推进”“可以递交”或“符合 CDE”措辞。
- 结论段固定保留 `[待医学负责人确认]`。

## 5. 推荐段落结构

- [段1] 研究目的、设计和分析定位，2–3 句。
- [段2] 主要终点和探索性结果概述，2–4 句。
- [段3] PK 关键发现和可解释限制，2–4 句。
- [段4] 总体 AE 与关键安全性事件，3–5 句，重要事件优先。
- [段5] 研究局限，包括样本、随访、缺失和可推广性，2–4 句。
- [段6] 条件化总体结论，1–3 句。
- 每段只整合已经在正文出现的信息。
- 不逐表重复所有数值。
- 不以研究目的为由淡化不利结果。
- 结果方向不一致时并列陈述，不强行综合为单一方向。

## 6. 常见退审问题

| 问题 | 如何规避 |
|---|---|
| 第 13 章出现前文没有的新数值 | 结果键必须在 confirmed-body 清单且哈希一致 |
| 只讨论有利结果 | 关键安全性事件分支强制优先陈述不利结果 |
| 探索性结果写成确证性结论 | 沿用前文章节的分析定位和限定语 |
| BLQ 被解释为系统暴露低 | 复用 PK 结论的可定量性和参数限制 |
| 有 SAE 仍写耐受性良好 | 关键事件非零时禁止有利概括 |
| 没有关键事件即写获益风险有利 | 零事件分支仍保留医学确认 |
| 把未提供资料当作阴性结果 | 关键绑定缺失即取消总体判断 |
| 形成开发推进建议 | 语义红线与固定分支双重禁止 |
| 形成申报就绪判断 | QC 权限边界禁止此类结论 |
| Synopsis 与正文结论不一致 | Synopsis 只从确认后的本节派生 |
| 研究局限写成内部流程说明 | 只使用 CSR 标准范围限定句 |
| 前文更新后总体结论未重跑 | confirmed-body 哈希变化即重新派生 |

## 7. 本节特有的易错点

- “总体结论”不等于申办方开发决策。
- “未报告”必须由完整零值支持，不能由清单为空推定。
- 关键安全性事件的医学意义不能只由计数决定。
- SAE 因果关系必须沿用经审核来源，不由本节判断。
- PK 暴露特征不能脱离 BLQ、LLOQ 和采样覆盖讨论。
- 探索性疗效结果不能与确证性成功条件混用。
- 不同分析集结果不一致时必须保留差异。
- 小样本研究的无事件结果不能被写成排除风险。
- 局部耐受性评分与编码 AE 必须在安全性综合中保持区分。
- 研究局限不能用工具自指或内部状态语言表达。
- 任何新表号或新结果都说明已越过 confirmed-body 边界。
- 前文待确认标记未关闭时，本节不能生成 clean 版总体结论。
