# 事实卡已审句式规范

## 用途

`authorized_surface_forms` 把「事实可以如何组织成一个完整断言」固定为人工审核过的句式。
它不是病种实词白名单，也不是允许模型拆字段自由拼接的词典。

## 字段

| 字段 | 要求 |
|---|---|
| `surface_id` | 卡内唯一的稳定 ID |
| `text` | 已审核的完整 CSR 句式，含需要原样保留的占位符 |
| `fact_ids` | 支撑该完整断言的全部事实 ID |
| `review_status` | 只接受 `confirmed` |
| `reviewed_by_role` | 审核角色，不写个人姓名 |
| `review_record_id` | 可回溯的审核记录 ID |
| `basis` | 审核依据的简短说明 |

## 示例

```json
{
  "surface_id": "SF-9-4-3-01",
  "text": "本研究采用中央随机化，并按等比例分配。",
  "fact_ids": ["S01", "S02"],
  "review_status": "confirmed",
  "reviewed_by_role": "protocol_fact_reviewer",
  "review_record_id": "M18-SURFACE-9-4-3-01",
  "basis": "已确认的方案事实句式"
}
```

## 发布校验

1. 段落声明的 `fact_ids` 必须包含句式所有 `fact_ids`。
2. 多字段段落仅允许使用完整已审句式；标签和值不可拆开重组。
3. 单字段段落可使用完整源值或固定缺口句。
4. 句式内的占位符必须来自其声明事实，不允许无源数值。
5. 未确认、缺审核记录、引用未声明事实或含内部流程语言时硬失败。
6. 事实卡和句式的规范化内容一并进入信封 SHA-256，任何改动都使旧信封失效。

## 人工责任

审核人需确认句式未改变事实含义、未输入因果或医学判断、未错配字段。
代码不把 `review_status=confirmed` 视为医学正确性的自动证明；它只确保确认记录存在、被哈希绑定且未被越界使用。
