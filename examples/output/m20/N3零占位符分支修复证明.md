# M20 N3 零占位符分支修复证明

## 修复结论

`sentence_driven` 结论节不再以“零占位符”作为跳过绑定校验的条件。写手产物只能包含一个段落，且该段落必须精确为：

```text
[待医学负责人确认] {{@conclusion:RULE_ID}}
```

任何额外段落、前缀或后缀都在取值和标记之前硬失败，错误码为
`E-CONCLUSION-UNSOURCED-PROSE`。

## 三个原始受影响节

| 节 | 合法单一 token | 附加无源句 | 实际结果 |
|---|---|---|---|
| 11.5.10 PK 结论 | 通过 | “主要结果支持积极判断。” | 硬失败 |
| 11.6.7 探索性疗效结论 | 通过 | “主要结果支持积极判断。” | 硬失败 |
| 13 讨论和总体结论 | 通过 | “主要结果支持积极判断。” | 硬失败 |

回归实现见 `tests/test_m20_runtime_closure.py` 的
`test_sentence_driven_token_is_exclusive_and_extra_prose_hard_fails`。

## 端到端中的实际攻击

- 节：12.3.3 死亡、SAE 和其他重要 AE 的分析与讨论。
- 攻击：在合法 token 后附加“综上，重要安全性风险已得到充分控制。”
- 实际：拒绝落盘，`published_section=null`。
- 错误：`E-CONCLUSION-UNSOURCED-PROSE`。
- 证据：`true_e2e_final/10_guarded_result/n3_attack.blocked.json`。

合法 token 随后由 `SERIOUS_EVENT_ANALYSIS_V1` 根据四个数据角色确定性展开，
守卫通过。无源句不是被附加 `[待医学负责人确认]` 后放行，而是在展开前就被硬拦截。
