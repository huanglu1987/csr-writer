# CSR Writer v1.1.0：输入清单与人工闸门清单

这份清单面向实际项目使用者。工具负责结构化抽取、确定性套值、受控起草、合卷和
可追溯报告；它不替代统计、医学、药物警戒、法规或 QA 的专业判断。

## 一、项目启动时必须提供什么

### 1. 外部原始资料

| 必需输入 | 建议格式 | 通常由谁提供 | 缺少时会怎样 |
|---|---|---|---|
| 最终或当前批准版研究方案及修订历史 | DOCX；每版附 SHA-256 | 临床运营/医学 | 无法确认研究事实、方法章节和删节理由；不得生成完整骨架 |
| 最终或当前批准版 SAP | DOCX；每版附 SHA-256 | 统计负责人 | 分析集、模型、缺失值处理和终点分析方法只能留缺口 |
| 经确认的 TFL shell | DOCX，数据锁库前冻结 | 统计编程 | 无法提前建立行列语义、表号和章节映射 |
| 结果 TFL | 优先每表一个 RTF；支持受控 DOCX 路径 | 统计编程 | 数值章节保留 `source_gap`，不能生成 clean 成品 |
| 表/图/清单发表编号规则 | JSON 或经确认映射表 | 统计编程/医学写作 | 正文交叉引用和第 14 章无法稳定生成 |
| 研究基本信息及签字信息 | 经确认的 study facts/标题页槽位表 | 申办方项目经理/法规 | 标题页、研究设计和责任人信息不能生成 |

所有原始资料只读使用。第一次进入项目时记录 SHA-256；版本变化必须触发重新核对，
不能用相同文件名覆盖旧版后继续运行。

### 2. 工具内部必须形成并由人确认的输入

| 内部输入 | 怎么形成 | 不确认会怎样 |
|---|---|---|
| `study_facts` | 人工填写五维 facts；工具只做反向扫描，不自动填值 | 路由、章节裁剪和白名单不得冻结 |
| 事实卡 | facts 转成一页 Markdown | 不允许要求审阅者直接批准 JSON |
| frozen `tfl_map` | 从 shell 自动提议，经分组审阅后冻结 | 结果到位后不得套值 |
| publication reference map | TFL 实体号映射到最终表/图/清单号 | 交叉引用不得入卷 |
| appendix status plan | 结合 E3 元数据、地区要求和 study facts | 16.0 清单及附录引用不得生成 |
| extraction fact cards | 从方案/SAP 指定章节抽取并核对 | 方法学章节不能进入受控起草 |
| review decisions | 与当次段落/计划 SHA-256 绑定 | annotated 可生成；clean 必须阻断 |

## 二、可选资料：提供后能多产出什么

| 可选输入 | 格式与来源 | 增加的产出或减少的缺口 |
|---|---|---|
| 随机化、盲态维护和揭盲记录 | 经批准记录或脱敏摘要 | 9.4.3、9.4.6 可形成有证据正文 |
| DMC/IDMC 章程与会议结论 | PDF/DOCX 或经确认摘录 | 期中分析和数据监查内容可落位 |
| SAE/死亡病例经审核事实卡 | 药物警戒/医学提供的结构化字段 | 12.3.2 可按逐字预审句生成；无卡时不得推断经过 |
| 编码字典版本 | MedDRA、WHODrug 版本登记 | 数据驱动 SOC/PT、ATC/药名行的预期来源更清楚 |
| 稽查状态和地区性附件登记 | 法规/QA 清单 | 16.0 的提交状态和位置更完整 |
| 参考文献与 claim ledger | 受控 bibliography registry | 第 15 章及关键主张可确定性生成 |
| 委员会、实验室和中心资料 | 经确认登记表 | 相应附录状态和方法描述可补齐 |
| 既有 COA 资料或“不开展新 COA 开发”的批准说明 | 方案/开发策略中的正式陈述 | 工具可忠实转述项目决定，但**不开发、验证或选择 COA**。若申办方决定不开展新的 COA 开发，建议提供经批准句式：“本项目不开展新的临床结局评估工具开发；如使用既有量表，其选择、授权及适用性依据另行记录。” |
| 视觉前置筛查环境 | LibreOffice + PyMuPDF（fitz）+ Pillow | 可在 Word 人工复核前检出未展开域、空白页和非 A4，并生成缩略图墙。未安装时流程照常完成，报告记录“未执行”，不改变既有发布判定。 |

## 三、全部人工闸门

| 闸门 | 谁负责 | 要做什么 | 不做会怎样 |
|---|---|---|---|
| 资料版本与哈希冻结 | 文档控制/项目经理 | 确认文件版本、来源和 SHA-256 | 流程不得开始或继续 |
| `study_facts` 确认 | 医学、统计、医学写作 | 阅读事实卡；确认 true/false/枚举及证据 | 路由不冻结，骨架不得发布 |
| 方案反向扫描核对 | 医学/医学写作 | 处理“方案有提示但 facts 为 false/空”的命中 | 可能漏章，保持人工待确认 |
| TFL shell 决策 | 统计编程 | 确认分析集、行列、版式继承、延后行和章节归属 | `tfl_map` 不得冻结 |
| 映射漂移裁决 | 统计负责人/数据方 | 每个 shell-only/result-only 选择预期变更或结果错误 | 严格套值继续硬失败 |
| 第 14 章发表编号确认 | 统计编程/医学写作 | 确认源实体到发表编号及书签 | 交叉引用不得解析 |
| 方法学抽取确认 | 医学写作/方案作者 | 核对逐字项、条目数和不可改变的限定条件 | 方法正文不能进入编排器 |
| 方法学有限自由正文复核 | 医学写作 | 判断改写是否忠实、自然、未增加卡外事实 | 只能保留 annotated 待审状态 |
| SAE 逐字预审句确认 | 医学负责人/药物警戒 | 逐例确认允许进入正文的完整句式 | SAE 叙述硬阻断 |
| 结论性表述确认 | 医学负责人 | 复核条件化分支、局限和医学解释 | clean 版不得生成 |
| 附录提交状态确认 | 法规运营/文档管理 | 确认 24 项状态、位置和可按要求提供说明 | 16.0 不得定稿 |
| clean 关闭决定 | 医学、统计、QA/申办方 | 逐项关闭 `[待确认]`、缺口和冲突，决定是否采用 | 仅 annotated 可用 |
| 自动视觉前置筛查（可选） | 医学写作/文档出版 | 在项目目录内渲染 clean/annotated，处理 A 类，阅读 B 类警告和缩略图墙 | 未检出渲染器时记录“未执行”；不取代下一道 Word 人工闸门 |
| 最终 Word 视觉复核 | 医学写作/文档出版 | 在 Word 中更新域，检查分页、目录、书签和表图 | 自动 OOXML 通过不等于视觉批准 |

LLM 建议型审核不属于发布门槛。它只列问题，不改正文；是否采纳由人决定。规则层
通过也不等于医学、法规或申报结论已获批准。

## 四、产出物分别给谁看

| 产出 | 用途 | 主要读者 |
|---|---|---|
| annotated DOCX | 含内部溯源、待确认和缺口，供逐项审核 | 医学写作、医学、统计、QA |
| clean DOCX | 所有人工决定关闭后生成的读者版 | 审阅者/后续出版流程 |
| facts card / routing report | 确认研究结构是否与方案一致 | 医学、统计、医学写作 |
| TFL map 与漂移队列 | 确认 shell、结果和发表编号 | 统计编程、医学写作 |
| guard/resolve report | 证明数值和正文从受控证据进入 | QC/开发审计 |
| unreferenced TFL | 按预期章节显示尚未被引用的表图 | 医学写作、统计 |
| bidirectional trace report | 证明方案→SAP→TFL→CSR 及反向路径 | QC/QA |
| QC report | 仅报告本次实际执行检查未发现的问题 | 项目团队；不作递交就绪结论 |
| visual QC report（JSON + Markdown） | 列出 A/B 类问题、页码和限制；缺渲染器时记录未执行 | 医学写作、文档出版、QC |
| 缩略图墙 | 按页缩略并以红/黄/绿边框标出 A/B/无命中页 | 医学写作、文档出版；用于快速扫描异常页 |

> 视觉检查基于 LibreOffice 渲染，与 Microsoft Word 的分页和字体回退存在差异。它位于最终 Word 人工闸门之前，是前置筛查，不替代在 Word 中更新域后的人工视觉复核。
