# M10 交付说明

## 范围与结果

本轮完成五项骨架缺陷修复、规格源纠偏和方案→study_facts 反向核对；未进入
M11 内容扩充。脱敏项目骨架的实际结果为：109 个官方/行业惯例标题保留、13 个
条件标题删除、20 个正式扩展标题；annotated 与 clean 的 OOXML 检查均为 `pass`。
完整回归为 183/183 通过。

### 五项缺陷

1. **结论节排序。** 渲染器按 `*_conclusion` 语义硬检查同级末位。当前 11.5.10
   PK 结论、11.6.7 探索性疗效结论和 12.6 安全性结论均通过；12.7 已移至
   12.6 之前。违反顺序会停止渲染，不依赖模块贡献顺序。
2. **编号断层声明。** 不重新编号。受影响章首在 annotated 和 clean 中都输出
   “本章以下小节因本研究设计不适用而未纳入”声明块，使用方案语言说明理由；
   字段/能力表达式只保留在内部 `omitted_sections.md`。无删节的章不生成空块。
3. **PK 归属。** 11.5 展开为 11.5.1–11.5.10，覆盖分析集、浓度、BLQ、参数、
   暴露、比例性、蓄积、外用条件、个体/异常和结论。外用 PK playbook 已把 BLQ
   比例、可定量时点、Cmax/AUC 可计算性及原因、LLOQ 和结论限制列为硬约束。
   PK+探索性疗效研究的 14.2 动态显示为“药代动力学和探索性疗效数据”；无 PK
   对照仍为“疗效数据”，且没有 11.5 扩展。
4. **附录清单。** 16.x 全部退出删除路径。16.0 五列表格现有 24 行，覆盖 23 个
   唯一官方附录项；同一 16.1.4 按“名单随 CSR / CV 留 TMF”拆为两行。四分类为
   CSR 必需 6 行、地区性 10 行、TMF 备索 3 行、不适用 5 行。
5. **删除依据。** `no supporting module` 不再是合法删除依据。11.4.3 和 11.4.6
   因 schema 中没有足以证明不适用的具体方案事实，被保留并进入人工确认队列。

## 规格源与标题覆盖

根目录和仓库副本的 `ICH-E3章节树.yaml` 均已还原为
`87ea56d599120e265c1649881a9d3ad1c08db540a91be13de6a2bd31a6bc0942`，第 3 章官方
中文保持“个例临床研究报告目录”。本地化“本临床研究报告目录”来自独立
`title-overrides.yaml`，记录官方中英文、本地化标题和理由，渲染报告同时记录覆盖
文件与官方骨架哈希。

`source-file-lock.json` 锁定四份根目录规格源及仓库骨架副本。常规 unittest 和
删除全部平台说明文件后的运行时回归都会复核这些哈希；本轮运行前后均一致。

## 方案→facts 反向核对

新增 `scan-protocol-facts` 和可配置规则表。它只在方案出现关键词而对应 facts 为
false/空时输出核对项，报告方案节、脱敏原文、当前值和问题；不调用模型、不写回
facts。否定性表述、背景文献和一般稽查条款不会被自动忽略。

- 配对方案：扫描 1653 条非空记录，产生 17 条命中。人工按事实问题归并后，判断
  1 个真实漏填风险：方案存在 DLT 定义性内容，而 `design.dlt_defined=false`；
  其余命中来自一般稽查条款、BE 指导原则、背景儿科资料和否定性 DLT 表述。
- 参照方案：扫描 1650 条非空记录，产生 9 条命中；本轮未判断出真实漏填，命中
  主要是一般稽查条款、BE 指导原则及背景老年资料，仍保留人工确认记录。
- 埋错：把参照 facts 的 `data_domains.local_tolerance` 在内存中改为 false 后，
  检出 77 条局部耐受性证据命中；源方案和 facts 文件均未修改。

上述“真实漏填/误报”是本轮人工判断，不由扫描器自动形成。

## 自主设计决定

1. 结论顺序以语义角色而非中文标题字符串判断，避免改名后失效；渲染完成前再做
   物理顺序审计，错误即阻断。
2. 同时激活 `M-PK-NCA` 和 `M-TOPICAL-PK` 时允许两个模块贡献同一 PK 子节；
   物化结构按节 ID 去重，仍保留两个驱动模块的溯源。
3. 编号断层声明使用章首一列表格，既形成可见区块，又不会伪装为新的编号小节；
   声明属于正式内容，因此 clean 版也保留。
4. 全部 16.x 标题保留。是否随报告提交只由状态表表达，避免把“留 TMF”误写成
   “材料不存在”。
5. 反向扫描不做否定词自动消歧。当前目标是防漏，不是让报告看起来干净；
   命中后的事实判断明确留给人工。
6. 方案位置由正文物理顺序中的数字标题推导，自动排除 Word TOC；真实 DOCX 的
   自定义样式不稳定，因此没有依赖特定 Heading style 名称。

## 遇到的问题

- 旧路由将父节贡献同时视为所有后代节的支持，可能使可选后代被无条件保留。
  本轮改为“贡献只保留精确目标及其祖先”，后代仍按自身事实条件判断。
- 真实方案的“稽查”大多是权利/职责条款，不证明存在稽查证书；BE、儿童、老年
  也常只出现在指导原则或背景文献。规则仍保留这些命中，由人工说明误报原因。
- 现有 facts 没有能证明 11.4.3/11.4.6 不适用的字段。为避免再次以实现缺口冒充
  方案依据，本轮选择保留并入队，而不是扩 schema 后自行猜值。

## 明确未完成

- 未实现每个 facts 字段的正/负证据对象及覆盖率报告（原任务 3.2）。
- 未把协议 SHA-256 持久写入 study_facts 并在版本变化时自动标记整份 facts 失效
  （原任务 3.3）。当前每次扫描会校验批准哈希、记录前后哈希并硬拒绝变化，但这
  还不等于 facts 文件自身的版本绑定。
- 未处理 M11 明确保留的 10.3 分析集、9.5.x 终点层级、estimand 位置、安全性
  专项分类或将 annotated 标记迁移为 Word 批注。

## M11 前建议

1. 先冻结 facts 证据对象和方案版本绑定，要求 false 也有“已查证无命中”证据；
   方案换版时只重扫受影响字段并明确失效。
2. 由医学负责人确认本轮发现的 DLT facts 差异，再重新路由，避免错误结构进入
   后续内容层。
3. 在当前稳定编号上补 10.3 分析集、9.5.x 终点/estimand 和 AESI、停药 AE 等
   安全性专项；不要再改编号策略。
4. 最后把 annotated 的内部高亮迁移为 Word 批注，并保持 clean 门禁与 OOXML 质检。
