# 在 Mac 上用 Antigravity 写 CSR

以下命令都发到 **Antigravity 对话框**。安装一次，以后每个研究直接从第 2 步开始。

<a id="install"></a>

## 1. 第一次用，复制这一条安装

```text
/goal 请在这台 Mac 上安装 CSR Writer。请将 https://github.com/huanglu1987/csr-writer/archive/refs/heads/master.zip 下载到临时目录并解压，用 /bin/bash 运行其中的 scripts/install-antigravity-mac.sh，看到“安装成功”后告诉我。
```

如果 Antigravity 提示允许运行安装脚本，点允许。看到 **安装成功** 后，新开一个会话，输入 `/csr-writer` 就能看到撰写技能。以后更新也发同一条安装指令。

<a id="workspace"></a>
<a id="draft"></a>

## 2. 给一个资料夹，用 `/goal` 写到 Word 初稿

在 Antigravity 打开研究项目，把方案、统计分析计划（SAP）、逐例数据和已有的定稿表放在同一个资料夹。复制下面这条，输入 `@` 时选中实际的资料夹。

```text
/goal 请用 csr-writer 从 @输入资料 生成 CSR 内部审阅初稿。按 SAP 补算能补的缺表，与已有定稿表对账。生成并打开 Word 核对正文、概要和附表，把 Word 路径发给我。缺哪些原件、哪些事项确需负责人决定，请在最后一次列清。
```

`/goal` 让 Antigravity 持续执行到你写明的目标，句子里的 `csr-writer` 指定使用已安装的撰写工具。日常起草发这一条就够了。

<a id="outputs"></a>

完成后，打开 **CSR内部审阅初稿.docx** 看报告，打开 **集中审阅清单.md** 看资料缺口和待决事项。两份文件默认在资料夹旁新建的目录里，例如 `输入资料_CSR初稿`。

<a id="commands"></a>

### 起草过程中，什么时候值得多用一条斜杠命令？

每行都是一条独立消息，遇到对应情况再发。开头的 `/csr-writer` 也能直接调用撰写技能，例如请它核查一张表的来源。

| 你遇到的情况 | 可以直接发给 Antigravity |
|---|---|
| 第一次接手研究，想先知道资料齐不齐 | `/plan 盘点 @输入资料，列出有效方案、SAP、已有统计表和逐例数据，告诉我哪些缺口会影响主要结果。` 看完盘点后，发上面的 `/goal` 开写。 |
| 统计表很多，想分头核查各章 | `/teamwork 请基于同一版首稿和已采用的统计表，分别核查疗效章与安全性章，把不一致的位置合成一张清单。` |
| 主要分析和敏感性分析结果不一致 | `/boost 请对照 SAP 和两张结果表，检查第 13 章应如何描述这处差异，列出有数据支持的解释和需要医学负责人判断的部分。` |
| 聊天已经很长，准备从起草转入审阅 | `/compact 保留研究资料夹、最新 Word、集中审阅清单的路径和待决事项编号。` 在首稿保存后发。 |
| 负责人看不懂清单里某个问题 | `/grill-me 请和我逐问澄清暴露表的差异，先说明两种算法及各自依据，再记录我的决定。` 要一次回复多项，直接用第 3 步。 |
| 项目结束，想把通用写法留给下个研究 | `/learn 请把这次确认的通用术语和表注写法整理成规则供团队审阅，项目数值留在本研究。` |

`/teamwork` 和 `/boost` 需支持这两项功能的付费方案。查公开文献时可用 `/browser`，需要定时重跑时可用 `/schedule`。[全部九个命令的示例](antigravity-csr-reference.md#commands) · [Antigravity 官方命令说明](https://antigravity.google/docs/slash-commands)

## 3. 收到负责人意见，怎样更新上一稿？

**先看要回答什么。** 打开首稿旁的 **集中审阅清单.md**，把统计问题交给统计负责人、医学问题交给医学负责人。请他们写清针对哪一项、决定怎么处理、理由是什么，并留下姓名和答复日期。可以一次回复多项，暂时定不了的留在清单里。

**再把原话交给 Antigravity。** “同一会话”就是刚才生成这份 Word 的聊天窗口。在那里复制下面这句，换一行粘贴你收到的实际回复，然后一起点发送。答复已写进 Word 或文本文件时，也可以在消息中输入 `@` 选中那份意见文件。若已换了聊天窗口，再用 `@` 选中原始资料夹和上一版输出目录。

```text
/csr-writer 请按这次收到的负责人意见更新上一稿。在新目录生成 Word，核对正文、概要和附录，告诉我改了哪里、还有哪些事项待决定。
```

**模拟例子。** 教学研究的清单里有一项 `TFL-2.1`。定稿暴露表写甲组 **4 人日**，按逐例给药记录算出 **3 人日**。下面展示写手收到统计负责人回复后，在聊天框里实际发送的一整条消息。示例中的决定和姓名仅用于演练。

```text
/csr-writer 请按这条统计意见另存新版 Word，核对正文、概要和附表，并列出仍待决定的事项。
模拟统计负责人，2026-02-02：TFL-2.1 采用逐例计算，甲组按 3 人日写。同一受试者同一天两次各半剂量，按本研究 SAP 只计一个给药日。
```

这次演练只答了这一项。新版 Word 的概要（第 2 章）、暴露正文（第 12.1 节）和安全性附表（第 14.3 节）都写入了甲组 3 人日，其余 4 项仍待决定。你只需传达实际意见，智能体负责整理答复记录和生成新版。
