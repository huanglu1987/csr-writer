# CSR Writer v1.1.0 Visual QC Design

## Scope

Add one optional, offline visual preflight layer after unified DOCX composition
and before the final Microsoft Word visual review.  No existing authoring,
guard, routing, resolution, composition, or release decision consumes this
layer.

## Architecture

`visual-qc` is a new CLI backed by `csr_writer.visual_qc`.

1. Read the DOCX without modifying it and record its SHA-256.
2. Load and hash the frozen visual configuration.
3. Detect LibreOffice.  If absent, emit JSON and Markdown with
   `status=not_run`, exit successfully, and produce no PDF.
4. Render the original DOCX to a project-local work directory using an isolated
   LibreOffice profile.  Reject system temporary work directories and reject a
   derivative whose signature is not `%PDF`.
5. Use PyMuPDF and Pillow lazily.  If either visual-only dependency is absent,
   emit the same non-fatal not-run report.
6. Analyse each rendered page and generate one or more marked contact sheets.
7. Emit deterministic JSON and Markdown reports.  Class A findings make the
   visual preflight status `blocked`; Class B findings remain warnings.  This
   status is not wired into the v1.0.0 release gate.

## Checks

### Class A

- Unexpanded fields: empty TOC/list directories, missing current/total page
  value, and rendered `Error!`/missing-reference text.
- Blank page: no text in the section-specific body band after known header and
  footer stories are excluded.
- Page size: portrait or landscape A4 with a fixed tolerance.

### Class B

- Body overflow: a non-header/footer text block crosses the section body band.
- Cross-page table without a repeated header: heuristic based on PyMuPDF table
  bboxes and consecutive-page continuation.
- TOC page mismatch: only evaluated when TOC entries are visibly expanded.
- Orphans: a heading left at the bottom of a page or a final one-character CJK
  line.

The DOCX layout parser reads each `sectPr`, its page size, margins, and
`headerReference`/`footerReference`.  Header/footer story text and text blocks
outside the body band are excluded before body-overflow analysis.  If a PDF
page cannot be mapped unambiguously to a section, the most permissive body band
for that page orientation is used so the first release favours warnings over
false blocking.

## Contact sheets

Pages render to bounded thumbnails.  Green indicates no finding, amber a Class
B warning, and red a Class A finding.  Each thumbnail includes its physical PDF
page number and finding codes.  A fixed maximum pages-per-sheet creates
multiple PNGs instead of one unbounded image.

## Calibration

The configuration is frozen and hashed before holdout construction.  A
separate generator that does not import the visual checker or its configuration
then creates a legal synthetic document containing portrait body pages,
landscape wide tables, a long table with a repeated header, headers/footers, a
chapter opener, and an appendix.  False positives are reported per page.  No
Class B check is promoted in v1.1.0 regardless of the measured rate.

## Test boundary

- Optional-renderer degradation returns 0 and records not-run.
- Invalid PDF signature, Class A failures, page-size failures, and field errors
  are covered by focused tests.
- Header text above the body band must not trigger overflow.
- Contact sheets are bounded and marked.
- Existing complete discovery and Codex platform-boundary tests remain green.
