# M20 真端到端与守卫收口设计

状态：用户任务书已明确批准实施边界；本文件将其固化为可复核设计。

## 目标与非目标

本轮先修正 N4/N3，再用一套结构陌生的脱敏合成输入从方案走到 CSR 双输出。
端到端的首轮失败是有效结果，不为跑通而修改夹具、放宽守卫或隐藏人工断点。
只有三条产出路径全部走通、人工阻断为零且守卫未放宽，才进入安装与冻结收尾。

本轮不使用真实临床材料，不自动填写 study_facts，不实现 BE，不修改既有夹具或四份
规格源文件。

## N3：sentence-driven 绑定门

PK 结论、探索性疗效结论和总体结论的起草面只允许：

1. 精确的 `[待医学负责人确认]` 标记；
2. 当前节唯一允许的 `{{@conclusion:规则ID}}`；
3. 不承载语义的空白。

条件化 token 在校验层代表完整消费该规则的全部绑定角色；绑定集合和顺序必须与规则
契约一致。零值占位符不是跳过校验的理由。token 前后出现任何附加正文，报
`E-CONCLUSION-UNSOURCED-PROSE` 并硬失败；不得仅靠语义标记放行。

## 陌生合成输入

研究设计采用成人偏头痛预防性治疗的Ⅱ期、单臂、开放标签研究。研究制剂、中心和
人员均使用脱敏名称。分析集使用 SAF、ITT、PPS，不出现 FAS/mFAS/SS/PKS。

新增三份输入：

- 合成方案 DOCX：含目标、单臂开放设计、给药、终点、安全性和一例合成 SAE 的受控事实；
- 合成 TFL shell DOCX：ICH 14.x 编号、空值 shell、分析集标记和一张仅存在于 shell 的表；
- 合成结果 TFL：包含结果值和一张仅存在于结果侧的表，且不回填 shell-only 表。

随机化和盲法 facts 明确为 false，路由不得生成 9.4.3、9.4.6。shell-only 表应报告
“无结果”；result-only 表应报告“未在冻结映射中”，不得静默并入 datapack。

## 端到端执行与断点纪律

流水线按以下顺序执行并为每步记录输入哈希、状态、错误码、人工介入和输出哈希：

1. DOCX 深度抽取；
2. 人工填写并校验 study_facts，反向扫描仅作核对；
3. 模块路由和结构裁剪；
4. shell 解析、提议、审阅决定和冻结；
5. 结果 TFL 套值和漂移报告；
6. datapack；
7. 确定性生成、方法学有限自由、SAE 逐字预审三条路径；
8. 占位符解析、三道数值守卫、条件化结论；
9. annotated/clean 装配；
10. 反向溯源和有界 QC。

首轮运行发现断点时立即记录，不修改夹具。必须修改代码才能继续时，先保存失败证据，
再以独立的“端到端解阻改动”条目实施，并重放同一输入。

## 测试与收尾门

- N4：8 个单元逐项验证生产方式、入口与发布门。
- N3：3 个合法 token 正例和 3 个“合法 token + 无源句”攻击。
- 路由：单臂研究不得出现随机化/盲法节。
- 漂移：shell-only 与 result-only 分别产生可区分状态。
- 文风：修正 9.4.1 字段倾倒，六病灶和句长不得退化。
- 回归：定向测试、完整 unittest discover、平台边界自检。

只有端到端三路径全通、人工阻断为零、无守卫放宽时，才生成安装文档、版本号、组件
哈希和交付包。否则本轮在断点报告处停止，不包装未达到门槛的工具。
