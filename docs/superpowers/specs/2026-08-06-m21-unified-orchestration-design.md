# M21 统一编排、映射漂移裁决与双端到端设计

## 1. 目标与边界

M21 关闭 M20 确认的两个发布阻断：

1. 确定性卷与受控正文卷没有统一编排器。
2. shell-only / result-only TFL 漂移没有标准化裁决和重冻结流程。

本轮不改变数值守卫、正向覆盖、SAE 逐字预审、结论条件化或人工闸门。
编排器不写作、不解析数值、不修改正文，只排序、编号和建立引用。

## 2. 方案比较

### 2.1 物理 DOCX 合并

直接拷贝两个 DOCX 的 `w:body` 元素。优点是改动小；缺点是样式、编号、
书签 ID、关系 ID、页眉页脚和 Word 域很容易冲突。不采用。

### 2.2 在已渲染骨架中注入两个卷

以 `project_skeleton` 为容器，按书签插入两卷内容。优点是可复用断层声明；
缺点是仍保留两套渲染逻辑，且容易让未经 loader 的内容直接注入。不采用。

### 2.3 单一语义编排计划

构造不可变 `CompositionPlan`：路由后章节、确定性 artifact、已过守卫正文和省略声明
先归一为有序节点，再由同一渲染器生成 annotated / clean。
该方案可中央化准入闸门、保留 Word 域并且便于字节可复现。采用此方案。

## 3. 统一编排器

### 3.1 准入层

编排器不接受任意 Markdown 或任意 `ResolvedSection`。输入必须是：

- `deterministic_bundle`：`status=pass`、`model_called=false`、52 个 artifact 且每个 validation 通过。
- 普通写手产物：通过 `load_resolved_section` 重新校验草稿、resolved 文本、meta、绑定和哈希。
- 方法学 / SAE 产物：通过 `load_constrained_resolved_section`，必须正向覆盖通过、
  文风通过、无 findings、零占位符、段落哈希一致。

准入记录包含 loader profile、证据文件哈希、段落哈希和参考实体。
任何 `{{...}}` 残留、未通过的 guard 报告或哈希不一致都硬失败。

### 3.2 编排计划

`CompositionPlan` 由以下内容确定性派生：

1. `ICH-E3章节树.yaml` 的官方顺序。
2. `title-overrides.yaml` 的本地化标题。
3. 路由 `section_plan` 的 retained / omitted / formal extension 决定。
4. 生产方式登记表和确定性 bundle。
5. 经准入层重新读取的受控正文。

一个 section 节点可含标题、确定性内容、正文段落、省略声明、域或书签。
编排计划序列化后哈希固定，annotated 和 clean 必须引用同一计划哈希。

### 3.3 省略声明与断层

`retained=False` 不生成标题，也不重排后续编号。编排器按章汇总省略项，
在该章首个可见位置插入正文声明。每项必须使用 `human_reason`，不能暴露字段表达式。
单臂 M20 夹具预期有 17 个省略项。

### 3.4 交叉引用与 Word 域

- `{{@ref:...}}` 仅在编排阶段转为 Word REF 域。
- 每个引用目标必须在终稿计划中有唯一书签；断链、重复或未声明目标硬失败。
- 3.1–3.6 的 TOC/TC 使用 `w:fldChar` + `w:instrText`，不保存静态目录文本。
- 表、图、附录书签由最终计划统一分配 ID，不复用分卷的局部 ID。

### 3.5 页面、页眉页脚和可复现性

- 页面与页眉页脚只从 `format-spec.yaml` 读取。
- 封面不显示页码；正文页码从 1 开始，正中显示 PAGE 域。
- 两个输出经同一个原子保存和 OOXML 校验流程。
- DOCX 使用固定 ZIP 成员顺序、1980-01-01 时间戳和固定压缩参数。
- 相同输入连续两次生成时，annotated 和 clean 均必须字节完全相同。

## 4. 映射漂移裁决

### 4.1 决策队列

严格套值仍先失败。以失败报告、冻结映射和结果解析为输入，为每个
shell-only / result-only 实体产生一个决策项。决策项包含：

- 表号、脱敏标题或标题哈希；
- 漂移方向、受影响值位数、预期 CSR 章节；
- 旧映射哈希、结果源哈希、决策队列哈希；
- 选项 `expected_change` 或 `result_error`。

### 4.2 决策与重冻结

决策记录必须包含角色、时间、队列哈希、每项决定和理由。

- 任一项未决定：`E-TFL-DRIFT-DECISION-PENDING`。
- 任一项为 `result_error`：生成退回数据方报告，不生成新映射。
- 全部为 `expected_change`：生成明示修订 candidate，保留旧版本、决策链和实体增删差异，
  再由现有冻结机制生成新版映射。

裁决流程不能根据标题或“看起来合理”自动选择。

## 5. 双端到端验证

### 5.1 M20 单臂开放夹具

重放方案抽取、facts、路由、shell 映射、漂移队列、裁决、重冻结、套值、
三条写作路径、统一编排、双向追溯和 QC。验收：

- 9.4.3 / 9.4.6 不出现；
- 17 个省略项均出现在正文省略声明中；
- 两个漂移实体均经显式合成决定记录处理；
- 严格套值通过；
- clean / annotated 均由同一计划产生。

### 5.2 Ib 随机双盲夹具

仅使用仓库内已有脱敏 M15 输入快照，不重新读取真实文件。运行相同编排器和裁决流程。
已有夹具是部分结果，差异不得静默忽略；无法合法裁决时必须保留阻断并停止收尾。

### 5.3 防后门和可复现性

- 伪造一个未过守卫的产物，统一编排器必须硬失败。
- 伪造一个有占位符的 constrained 产物，必须返回 resolver-required 错误。
- 每套输入连续合卷两次，对 clean / annotated 分别进行字节 diff。

## 6. 收尾闸门

只有两次端到端均满足以下条件才进入收尾：

- 阻断性断点为 0；
- clean / annotated 完整且经 OOXML 质检；
- 守卫配置和攻击回归未放宽；
- 相同输入的两次输出逐字节一致。

若通过，产出 Codex 安装文档、面向使用者的输入/人工闸门清单、平台边界复验、
版本号、哈希清单和 M1–M21 机制沿革。若任一条不通过，仅交付断点和证据，不收尾。

## 7. 错误码

| 错误码 | 含义 |
|---|---|
| `E-COMPOSE-ADMISSION` | 产物没有守卫通过证明 |
| `E-COMPOSE-UNRESOLVED` | 存在未解析占位符 |
| `E-COMPOSE-ORDER` | 章节顺序或编号断层与计划不一致 |
| `E-COMPOSE-REF` | 书签或 REF 域断链 |
| `E-COMPOSE-FIELD` | TOC/TC/PAGE 域被压平或丢失 |
| `E-COMPOSE-REPRODUCIBILITY` | 相同输入字节不一致 |
| `E-TFL-DRIFT-DECISION-PENDING` | 漂移队列未全部裁决 |
| `E-TFL-DRIFT-RETURN-TO-DATA` | 存在结果错误决定，不得重冻结 |
| `E-TFL-DRIFT-DECISION-BINDING` | 决定记录与队列哈希不匹配 |

## 8. 设计自审

- 没有新的正文写入接口；编排器只能调用已有严格 loader。
- 没有复制 DOCX 内容树；避免关系 ID、样式和域冲突。
- 没有让漂移裁决自动选择结果。
- 没有修改现有只读材料或旧夹具。
- Ib 夹具若因部分结果无法合法关闭漂移，必须保留断点，不为收尾削减分母。
